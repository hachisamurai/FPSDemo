# 四类枪械开火与怪物受伤音效

## 换弹动作音效接入（2026-09-21）

按后续“换弹音效匹配动画动作”的需求，新增独立的21个原创短机械声，覆盖四枪八套普通/空仓换弹。开火Cue及其12个变体不变；狙击枪的BoltOpen/BoltClose只在空仓换弹动作的拉栓阶段触发，不在每次开火后额外播放。

源文件为 `Art/Audio/Reload/SW_Reload_*.wav`，48kHz/PCM16/Mono，峰值-6dBFS；由 `Tools/Audio/build_reload_audio.py` 生成阻尼金属模态、短撞击与摩擦噪声，不包含外部录音。游戏资产为 `/Game/Audio/SFX/Weapons/Breach/Reload/` 下同名SoundWave。八个动作时间表来自 `Art/Weapons/Animations/weapon_animation_manifest.json`，导入到四个武器子AnimBP的 `AnimSet.TacticalReload/EmptyReload.SoundEvents`。21指独立声音资源数，同一资源可以被普通/空仓两种动作共用。

`UDemoWeaponAnimationComponent` 按本次换弹归一化进度跨越事件点时播放对应SoundWave，游标先消费后发声，低帧率跨过多个点也不重复；音量默认0.75、音高1。拔匣、插匣、压实与拉机柄分别是短声，不播放整段混合WAV，因此改ReloadSeconds后事件仍随动作伸缩。返回的AudioComponent由本次动作持有，结束/取消/销毁时停止并销毁，旧声音不延续到新武器。音效不提交弹药，也不更改GAS计时；无声卡时记录播放组件为空但玩法继续。

通过 `Tools/Unreal/import_fp_weapon_animations.py` 随动画统一导入，`validate_fp_weapon_animations.py` 在新Editor进程检查声音引用及事件升序。`Tools/Audio/build_reload_audio_previews.py` 生成8条按同时间表合成的试听，保留0.3秒尾部并复读验证无削波；`Art/Audio/Reload/Previews/index.html` 可直接打开。`Tools/Audio/build_reload_video_previews.py` 将UE真实录帧的TSV游戏时间与这些声音合成同步视频，视频音轨是可追溯的试听混合而非声卡实录。

改变动作关键帧时先同步机械manifest再统一重建动画/声音事件，不能另外添加播放相同声音的Notify。详细运行流程、失败边界、调用日志、依赖与验证见 [武器系统：第一人称四枪换弹](../武器系统.md#第一人称四枪换弹动画层与同步音效2026-09-21实现)。以下“四枪版本”章节描述独立的开火音色任务，其取消额外拉栓声的范围是开火反馈。

## 当前四枪版本（2026-09-21）

### 目的与制作范围

依据用户提供的 `D:/NewDownload/Codex_四类枪械音效制作规范.docx`，让当前工业风武器在接近的源峰值下仍有不同的声音结构。文档是音色参考；用户明确允许减少制作量，因此将原建议 18 个开火变体缩减为 **四枪各 3 个，共 12 个**。该开火任务取消了额外狙击拉栓声，开火导入器不制作/导入独立拉栓或换弹音效；后续换弹动画的机械声由上节专用管线管理。短滑套/自动机撞击只是开火声内的轻机械层，不驱动枪械动作。

| 枪型 | 源文件时长 | 独立配方 | Cue 随机音高 |
|---|---:|---|---|
| Pistol 手枪 | 0.28s | 1.7–5.9kHz 短拍击、小型 210–275Hz 枪体、轻滑套；紧凑干声 | 0.97–1.03 |

各枪使用独立层结构、带宽、包络和随机种子，绝非把同一 WAV 改音高。整体采用 35Hz 因果高通、头尾渐变，保留瞬态动态；没有对整个混音做砖墙压缩。所有源文件统一 **48kHz / PCM24 / Mono / -3dBFS 样本峰值**，不把高伤害简单等同于更高源音量。程序化游戏音效不声称是真枪录音；耳机和小音箱上的最终听感仍需人工试听。

## 目的与设计

开火、怪物命中各三个变体，共六个原创 Python 合成 WAV。全部 **0.4 秒 / 48000 Hz / 24-bit signed PCM / Mono**，保留用户指定 `SourceAssets/Audio/SFX/Weapons/Sword/` 路径；Sword 为命名约定，不改变射击玩法。

Fire 保留快速带通噪声破风、下降扫频、低频枪身冲击和轻微金属衰减模态。Hit 根据肉体受击要求使用独立 `synthesize_flesh` 配方：低频阻尼闷击、9ms皮肤拍击、四次不规则湿润组织挤压和柔和回弹，完全去掉开火式破风、高频扫频与金属尾音。命中主要能量集中在前0.12秒，文件仍保留0.4秒以容纳自然衰减。三个变体的种子、低频中心和挤压时序不同，不是复制改名。头尾淡变、去直流和 TPDF 抖动减少切割爆音与量化失真。纯 Python 标准库，无外部采样依赖；最终听感仍需人工确认。

## Sound Cue 配置

两个 Cue 均为：`3 × WavePlayer → Random → Modulator → Output`。

| 参数 | 设置 |
|---|---|
| 变体选择 | 等权 1/1/1，Random Without Replacement，每轮三变体各用一次；跨轮边界可能重复 |
| Pitch | 0.95..1.05，每次发声随机 |
| 随机音量 | -1.5..+1.5 dB，即线性倍率 0.841395..1.188502 |
| Cue 与播放接口乘数 | Volume/Pitch 均为 1，避免二次随机 |
| 循环 | 关闭；pitch 变化后实际时长约 0.381..0.421 秒 |
| Fire 衰减 | 3D 球形线性，内圈 150 cm，Falloff 3000 cm，3150 cm 外静音 |
| Hit 衰减 | 3D 球形线性，内圈 120 cm，Falloff 2200 cm，2320 cm 外静音 |
| 分支预裁剪 | 关闭，保证三个变体参与选择 |

Modulator 采用线性振幅均匀分布，端点按 `10^(dB/20)` 转换，不宣称 dB 均匀分布。每种 Cue 引用独立衰减资产，可单独调距离。

概念参考 [Epic Sound Cue Reference](https://dev.epicgames.com/documentation/unreal-engine/sound-cue-reference?application_version=4.27) 的 Random/Modulator；API 兼容性以本机 UE5.4.4 源码和实际运行结果为准。

## 运行流程与所有权

**开火**：输入 → GAS Fire 检查与 Commit → `ADemoCharacter::PerformShot` → 当前武器`ExecuteCommittedShot` → 射线/聚合伤害 → 在配置的MuzzleSocket调用 `DemoWeaponAudio::PlayAtLocation`。缺少MuzzleSocket时回退到相机前70cm、右15cm、下10cm并记录日志。FireSound由各武器BP配置，霰弹每次触发只播一次开火，同一目标聚合一次伤害/受击声音。空射也发声；空弹匣、装填、冷却、安全区等拒绝激活时不发声。

**命中**：射线/其他伤害 → Health GE → `ADemoEnemy::OnHealthChanged` → 完成初始配置、尚未死亡且 `NewValue < OldValue` 时在敌人位置播放 Hit Cue → 再处理致命伤害和死亡奖励。`bHealthConfigured` 在 Configure 批量写入期间为 false：默认100生命降到小怪60生命也是初始化，不能误播。治疗、零伤害不播；致命一击先播放再隐藏敌人。

Actor 的 UPROPERTY 强引用 Cue，CDO 硬引用为 Cooker 提供依赖。播放组件用 `SpawnSoundAtLocation(...bAutoDestroy=true)`，归 World 管理，不附着死亡敌人，因此敌人 0.1 秒后销毁不会截断肉体受击的自然衰减；切图随 World 清理。

当前范围是现有单人玩法，不实现多人广播/预测。专服、无音频设备、不可闻位置或资产缺失跳过播放并记录原因，不影响伤害。
