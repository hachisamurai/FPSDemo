## 本机启动

1. `Backend/.env.local.example` 复制为 `Backend/.env.local`。后者已加入Backend/.gitignore，不能提交、截图或粘贴密码。
2. 设置 `Mongo__ConnectionString` 为Atlas Drivers页面提供的完整URI。去掉用户名/密码占位符尖括号；用户名是Database User，密码不是Atlas网页登录密码。特殊字符需要URI百分号编码。
3. `Mongo__Database` 使用项目专用库，例如fpsdemo_dev；不要使用admin/local/config。数据库用户需要项目库的读写、创建集合与索引权限。Atlas IP Access List允许运行后端的电脑公网IP。
4. 在项目根PowerShell启动：

```powershell
& .\Backend\Tools\Start-Backend.ps1
```

脚本加载环境，不将密码放进进程参数。默认先编译；确认二进制最新时可用 `-NoBuild`。便携.NET SDK放 `Saved/BackendRuntime/dotnet`，缺失时由Install-Runtime下载官方SDK并校验官方SHA512，不改系统全局dotnet。服务启动会创建缺失集合及索引，不清空现有库。

默认API只监听 `http://127.0.0.1:5087`。`GET /health` 实际ping数据库后才成功；日志 `DATABASE_READY` 表示初始化通过，不能仅凭进程存在判断可保存。关闭此后端进程只让游戏进入离线重试，不删除云数据。

`Config/DefaultGame.ini` 的 `/Script/FPSDemoOnline.DemoApiClient`：

```ini
; URL必须加引号，避免UE配置解析将双斜杠识别为注释。
BaseUrl="http://127.0.0.1:5087"
; 每次HTTP超时秒数，代码约束2..30。
TimeoutSeconds=8.0
; 仅对打包游戏有效；编辑器硬性本地模式，不受此开关影响。
bEnabled=True
```

发布到远端时把BaseUrl改成自己的HTTPS API地址，两台设备使用同一后端。不要把MongoDB URI填入BaseUrl。公网部署的证书、反向代理、限流和服务托管不属于本次本机启动脚本。

环境字段：Mongo__ConnectionString是Mongo官方URI；Mongo__Database决定固定项目库；ASPNETCORE_URLS决定后端监听；Profile__AllowOfflineProgress=True接受单人离线通关并标记offline_accepted。设False会拒绝离线通关，当前尚无权威游戏服务器成绩替代入口。

## 跨设备匿名账号迁移

当前没有用户名登录UI。若要在另一Windows设备继续同一匿名账号，先在原电脑导出密码保护的账号文件，再在新电脑**第一次启动游戏前**导入。要求PowerShell 7，两个项目使用相同API；真实密码通过隐藏交互输入，不放在命令参数中。

```powershell
& .\Backend\Tools\Transfer-CloudIdentity.ps1 -Mode Export -File D:\Backup\FPSDemo.cloudkey
# 将加密文件复制到新电脑，并用独立渠道保管其密码；在新电脑执行：
& .\Backend\Tools\Transfer-CloudIdentity.ps1 -Mode Import -File D:\Backup\FPSDemo.cloudkey
```

脚本导出不覆盖既有目标，导入拒绝覆盖新电脑已有身份。已有另一账号时需先做明确的账号备份/迁移，不自动合并。打包游戏请追加 `-IdentityFile <该游戏实际Saved/Cloud/Identity.bin路径>`；留空才使用工程Saved。编辑器本地模式没有云账号迁移需求。迁移账号后，云端下载检查点即可，不必复制sav。

迁移包JSON不支持注释：version=1固定PBKDF2-SHA256/600000次、32字节密钥；salt=16字节、nonce=12字节、tag=16字节、ciphertext均Base64；AES-256-GCM校验密码与完整性，导入后以新Windows用户DPAPI重新封装。密码或文件丢失且原身份文件也丢失时，当前没有账号找回服务。商业化应替换为平台登录/受控账号恢复。

## 常见失败与维护

- TimeoutException：检查DNS、Atlas IP允许列表、网络/TLS、集群状态；启动最多等待15秒选服。
- MongoAuthenticationException：检查Database User用户名/密码/authSource；不要用Atlas网站密码。
- 400：查看稳定code；客户端/后端协议或校验不一致需修复，不能无限重发坏请求。
- `invalid_json`且登录200：优先核查**运行中的后端**是否支持客户端检查点版本。修改Contracts.cs或重新打包游戏不会更新已经启动的API进程。运行`Start-Backend.ps1`会先构建，再启动新版；已有服务需正常停止后再启动，避免旧进程仍占用5087。不要通过删除客户端Identity.bin或同步队列绕过协议错误。
- `/health`同时提供`checkpointVersions`（当前支持1/2/3）和`serviceBuild`（运行中程序集的MVID标识，不是版本排序值）。本机和公网应返回相同标识；缺少这些字段说明仍是旧部署。`protocolVersion=2`只是同步信封版本，并不证明支持V3检查点。新增检查点协议时同步维护DTO、校验、health能力列表和测试，再部署服务。
- 409：版本变化重新拉取；slot_conflict由大厅选择；request_id_reused/run_id_reused停止并检查数据，不能强制覆盖。
- 本地损坏/磁盘失败：先恢复有效文件/权限，再点重试；服务器成功不等于本地确认已落盘。

新增入口、HTTP回调、定时回调及拒绝分支有日志；正文、Bearer、DPAPI明文、数据库密码不记录。重点标记：DATABASE_READY、CLOUD_ACK、CLOUD_FAIL、PROFILE_SAVE、RUN_SAVE。HTTP路由日志只含方法和路径。高频日志按项目调试配置调节，不删除入口埋点。

影响文件与双端维护清单见设计文档。尚未验证Shipping配置、真实第二台电脑、恶意压力测试、Atlas备份恢复或多人联网；Development打包与账号迁移脚本的本机加密往返测试不等同于第二台电脑验证。
