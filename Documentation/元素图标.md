# 元素状态与弹药图标

## 目的与设计

为当前 BREACH 战术 UI 提供六张独立透明图标。沿用深蓝灰界面底色、青色强调、灰白金属与暖金色配色，采用粗轮廓、大色块和轻微切面厚度。火焰以橙金色表达燃烧，冰块以冰青色立方体表达冻结；四种子弹共享左下至右上的方向，普通弹仅保留金属弹体，元素弹通过火焰、冰壳和被贯穿的装甲板区分，不依赖文字或颜色单独识别。

火焰、冰块用于敌人血条旁的状态图标：资产为带厚度观感的二维透明贴图，另保留世界材质供其他场景使用。当前原生敌人采用头顶世界位置投影到Canvas的屏幕空间显示，始终水平正对屏幕。图标模块不实现元素伤害、持续时间或叠层效果。

## 核心流程与依赖

`Tools/Unreal/import_element_icons.py` 通过 UE Editor Python 的 `AssetImportTask` 导入源图为 Texture2D，设置 UI 压缩、sRGB、保留 Alpha、边缘 Clamp、无 Mip 和 Never Stream，再保存资产。当前源图不是二次幂，因此不直接为原图启用常规 Mip 链；如以后用于大量远距离敌人，应另行制作合适尺寸的运行时版本并重新做远距采样验收，原图继续保留。

前两张状态图额外创建 Surface 材质，采用 **Unlit + Translucent + Two Sided**。`IconTexture` 参数的 RGB 直接接 Emissive，A 接 Opacity；不额外放大发光，不关闭深度测试，避免图标穿墙。材质不负责位置、朝向、显隐或状态时长。

脚本只创建本模块的新资产，已有同名纹理复用且不替换源像素，已有材质保留节点以避免覆盖人工修改；遇到错误类型、缺少源图、连接或保存失败，抛出异常并记录失败。所有功能函数有 `[ElementIcons]` 入口日志。脚本不运行游戏实例、联网或改变关卡、存档、数值配置。依赖项目已启用的 PythonScriptPlugin、EditorScriptingUtilities，不引入新插件。

## 使用与配置

### 敌人头顶进度条与状态图标

`ADemoEnemy`已移除旧`HealthLabel` TextRender及朝向玩家的旋转更新。`ADemoHUD::DrawHUD → DrawEnemyStatusBars → GetEnemyStatusScreenAnchor`每帧读取当前World的活敌人：2026-09-21骨骼接入后优先取唯一主SkeletalMesh的`HealthBar` Socket世界位置，避免Boss背环挡住血条；无网格/挂点时回退Actor加世界Z偏移（小怪80cm、Boss160cm）。Canvas只绘制水平矩形，不继承敌人或摄像机Yaw/Pitch/Roll。血条跟随敌人头顶的屏幕位置，始终正对屏幕；不是固定世界朝向的平面。Boss原有顶部总血条保留。依赖、资产配置与动画回归见[敌人动画模块](敌人模型骨骼与动画同步设计.md)。

血条为120×10设计像素，读取GAS当前/最大生命并钳制比例0..1，上方保留等级与数值；小怪红色、Boss橙色。按用户要求移除血条外围、文字及图标的黑色底板，也不绘制进度条的深色空槽，已损失血量区域透明，仅剩余生命显示彩色填充；其他玩家/Boss顶部HUD的通用Meter不变。图标在血条右侧紧凑排列，每张32×32等比contain，保留原RGB/Alpha并直接叠加场景；状态增减不移动血条中心。全HUD按1280×720等比缩放，距离不会缩小图标。无Tag不显示；`Debuff.Burn`显示火焰，`Debuff.Chill`或`State.CC.Frozen`显示冰块。当前正常玩法只允许携带一种特殊弹药出战，双图标截图仅是显示层的测试夹具；HUD读标签不承担弹药互斥验证。仅冰霜免疫不显示冰冻，不把Tag数量当GE叠层。

这三个Native Tags在`GAS/DemoTags.*`注册，名称与[弹药Debuff设计](弹药类型与Debuff设计.md)一致。后续生产GE需授予/移除相应标签；HUD不施加GE、不处理计时、不依据玩家装备类型猜测敌人状态。当前弹药效果仍待实现，因此普通射击不会凭空添加图标；测试通过隔离ASC标签夹具验证显隐。

`DemoHUD`类默认值`Demo | Enemy UI`可替换`EnemyFireIcon`/`EnemyIceIcon`，以及调整`EnemyStatusMaxDistance`（默认6000cm）。两张常驻共用贴图使用CDO强引用，确保Cook依赖可追踪；不为每只怪加载一份、不在Draw中读盘，不使用原世界Surface材质。缺失贴图时显示“火/冰”文字并在HUD构造时记录Warning。该配置不写玩家存档、不复制。

镜头后方、屏幕边缘放不下整个面板、超过显示距离、死亡/隐藏及非Combat阶段不绘制。投影和距离检查之后才向敌人中心做Visibility射线，忽略玩家与该目标，墙体和其他敌人可遮挡；这是中心视线规则，不代表精确像素遮挡。狙击镜只允许完整面板落在圆内；暂停/终端等模态页优先，不穿透菜单。HUD不缓存敌人指针，不新增敌人委托/计时器，换World自然停止旧对象绘制。密集敌群仍可能有血条互相重叠，当前未实现自动错位排版。

修改敌人体积或镜头显示规则时同步检查HealthBar挂点、回退偏移、遮挡和狙击镜边界；大规模怪群需另行评估每帧遍历/射线成本。新增函数入口使用DEMO_LOG_TICK或DEMO_LOG_CALL，裁剪属于高频正常条件，不逐敌人刷Warning。

2026-09-21骨骼挂点接入回归：`Saved/Logs/EnemyAnimationHUDRegression.log`输出`DEMO_ENEMY_STATUS_SUCCESS`，真实渲染验证状态变化、相机旋转、距离/遮挡裁剪及死亡当帧隐藏。模型死亡延迟改为1.65秒，但IsAlive当帧变false，所以尸体不会继续显示生命或元素图标。

### 弹药 UI

四种弹药纹理可直接用于 Canvas/UMG Image，建议 40–64px 正方形展示区；32px 可辨认类别，但装甲板和冰壳细节更少。普通弹是无元素效果时的基础显示，纹理本身不改变伤害规则。绘制颜色默认白色，保留纹理自己的色彩和 Alpha；不要用当前 UI 的青色统一乘色，否则火焰与穿透颜色会偏移。资源绑定到实际组件、蓝图或配置软引用后再验收 Cook 收集，运行时不读取 SourceAssets PNG。
