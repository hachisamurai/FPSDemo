# 战役配置、怪物等级与难度

## 目的与设计

把基础怪物模板、等级成长与击杀银币/整轮通关金币、全局难度分开维护，避免把三个倍率重复写入怪物代码。十个逻辑关卡复用三个物理白模区；第 N 关怪物等级必须为 N。图片背景大厅提供开始游戏、设置和退出；开始后先选择存档。难度选择已移至初始安全区下一关终端，设置已接入分辨率、画质、鼠标和显示模式，详见[暂停与存档](暂停设置与检查点存档.md)。大厅美术配置见 [UI设计与接入](UI预览设计.md)。

大厅使用已加载的白模 World，但不展示场景、不生成交互物/怪物，角色禁用移动；没有额外大厅地图。新建存档进入安全区，已有存档恢复最近检查点，旧Victory档进入可玩安全区；初始入口明确选难度后开始第一关。前九关清关后玩家留在原区域，中心生成升级与下一关终端，选完免费奖励进入Intermission。玩家死亡结算后返回安全区重开第一关，清空银币/临时升级但保留金币/永久成长与难度；胜利返回安全区同样清空银币/临时成长并保留金币/永久成长/解锁，可装备新解锁主武器并选择更高难度；系统错误可返回大厅。难度仅在第0关安全区允许修改，第一关出发后锁定。当前仅单人Standalone/PIE，复制字段不是完整多人支持。

## 计算规则

```text
等级生命 = 怪物模板 BaseHealth × 等级 HealthMultiplier
最终生命 = max(1, 等级生命 × 难度 HealthMultiplier)
等级攻击 = 怪物模板 BaseAttackPower × 等级 AttackMultiplier
最终攻击 = 等级攻击 × 难度 AttackMultiplier
小怪银币 = 等级 EnemyCoinReward
Boss 银币 = 等级 BossCoinReward
```

先算等级再算难度，中间不取整。GAS Health/MaxHealth/AttackPower 保留浮点精度，HUD 生命显示整数。两种货币都是非负整数，不随生命或难度乘算，也不随机掉落、不生成实物拾取物；无尽的银币另外应用 SilverGrowth。生成时复制数值到实例，死亡不再查表，防止热改导致同一怪物的击杀奖励变化。近战、弹体和原 Boss 范围技能读取 GAS AttackPower；升空俯冲沿用独立技能规定的固定50伤害，详见[Boss升空俯冲](Boss升空俯冲.md)。

例如 Lv5 小怪基础生命 60、攻击 9，等级倍率 1.9/1.4：等级属性为 114 HP、12.6 攻击；困难 1.5/1.4 后为 171 HP、17.64 攻击，击杀仍为 18 银币。

## 资产与字段

运行时读取 `/Game/Data/DT_Enemies`、`DT_Difficulties`、`DT_Levels`、`DT_Endless`；原生行类型分别为 `FDemoEnemyRow`、`FDemoDifficultyRow`、`FDemoLevelRow`、`FDemoEndlessRow`。GameMode 的 `EnemyTableAsset/DifficultyTableAsset/LevelTableAsset/EndlessTableAsset` 软引用可在派生类替换，加载后强引用保活。JSON 源码保存在 `Config/Combat`，不支持注释，因此本节承担字段说明及修改原因。

## 修改与导入

新增奖励字段由`Tools/Unreal/upgrade_economy_tables.py`迁移：只给未配置的难度行填500/750/1000，保留既有战斗参数并由Editor保存；移除关卡表废弃ClearGoldReward。重跑保留已配置非负奖励。旧upgrade_currency_table.py入口转发该脚本。

在 UE Content Browser 打开 `Content/Data` 下 DataTable 修改行并保存即可，下一次运行生效，不需 C++ 重编译。为保持源码可复现，应同时维护 `Config/Combat/*.json`。修改 C++ 行结构则先编译 Editor，再导入。

批量编辑 JSON 后执行以下命令。工具会原位更新这四张表，**覆盖表中的编辑器手改值**，不会删除其他资产；字段名拼错、重复行和导入失败会报错。先把希望保留的编辑器改动同步到 JSON。源文件是自定义导入流程，不依赖编辑器 Reimport 元数据。

```powershell
& 'F:/UE5.4.4/UnrealEngine-5.4.4-release/Engine/Binaries/Win64/UnrealEditor-Cmd.exe' 'F:/UE5.4Project/FPSDemo/FPSDemo/FPSDemo.uproject' -run=pythonscript '-script=F:/UE5.4Project/FPSDemo/FPSDemo/Tools/Unreal/import_combat_tables.py' -unattended -nullrhi -nosound '-abslog=F:/UE5.4Project/FPSDemo/FPSDemo/Saved/Logs/CombatImport.log'
```

成功日志 `COMBAT_IMPORT_SUCCESS`。导入工具依赖编辑器 Python/EditorScriptingUtilities，游戏运行不依赖 Python 或磁盘 JSON，只读取 `.uasset`。四张表使用原生构造函数赋值的软路径；不能以编辑器能加载为依据假定 Cook 已收集。`Config/DefaultGame.ini` 在 `[/Script/UnrealEd.ProjectPackagingSettings]` 中用 `+DirectoriesToAlwaysCook=(Path="/Game/Data")` 明确收集表资产；武器蓝图和输入另由 `/Game/Weapons` 规则收集。更换表目录时必须同步规则，并检查 Cook/Stage 输出。Shipping 验收仍需单独执行。

已有项目升级地狱/无尽请把上述命令的脚本改为 `Tools/Unreal/upgrade_challenge_tables.py`。该增量脚本只在缺失时追加 Hell 行、创建 DT_Endless，保留现有三难度及怪物/等级表调参；可重复执行，成功标记 `CHALLENGE_TABLES_SUCCESS`。本次实际采用该增量入口，资产均由 Unreal Editor 创建/保存，没有手写二进制 uasset。

## 执行流程与接口

1. `StartPlay` 载入四张表，`ShowLobby` 显示大厅并冻结角色；默认普通，无尽配置仅在选择/生成无尽时要求有效。
2. 开始按钮打开存档页；新建/选择有效槽后旅行，由`RestoreCheckpoint`调用`StartRun`校验配置并重建安全区，再恢复所保存阶段。
3. 初始入口弹出难度，`SelectDifficulty`验证枚举及Hub第0关；选择后调用`StartNextLevel`。`GetLevelConfig/GetSpawnStats`在传送和生成前完成解析，`Resolve`先等级、后难度运算。
4. `ADemoEnemy::Configure` 一次性写入 GAS 属性和实例等级/金币快照，禁止重复配置；初始化降低生命不会误播受伤音效。
5. 生命归零由 GAS 回调通知 GM；确认死亡且从注册集合移除成功才按`GetCoinReward()`加银币。重复、未注册、活怪通知拒绝。
6. 全部敌人死亡后下一帧 `FinishLevel`：1..9 关原地补给、当前 ArenaIndex 中心生成一对终端、免费选择后进入 Intermission；前九关金币为0，10关切换Victory后按难度VictoryGoldReward发金币，恢复永久金币成长基线并清空临时成长/银币，无第十一关终端。Boss 存活不能提前清场。下一关开始前销毁终端，不在复用场景中累积。
7. 实际玩家死亡后，确认重开会把当前槽重置为新的Hub检查点，再重建World/PS/ASC；进度/银币/临时强化归零，保留金币/永久金币属性及价格/解锁/难度。没有活动存档的开发World使用GI临时值快照重开。配置/生成错误返回大厅；胜利走ContinueAfterVictory清空银币/临时成长并保留金币/永久成长/解锁回Hub，以新RunId开始下一轮。详见[关卡与经济](关卡与经济.md)。

## 边界、失败与维护

- 表缺失/行类型错/引用错/数值超界/NaN/无穷大，开始失败留在大厅显示原因；不静默退回硬编码。局内下一关发现表错误则失败终局，可返回大厅修复重试。
- 数量合法仍可能因场景碰撞无法生成；生成失败明确终局，不能伪装成清场。增大怪物数量、改变布局后需检查出生点间距。
- 击杀银币按怪物等级直接到账，0 是合法值；修改已生成怪物的表行不会改变该实例奖励。不同模板目前共用同等级小怪银币，若未来不同种类有不同掉落，应扩展为“等级×模板”奖励表并同步验证器。整轮通关金币独立读取难度表的 `VictoryGoldReward`，不受击杀奖励倍率影响。
- 刷怪节奏统一为每5关加入远程小怪、每10关在三类小怪之外追加Boss；表仅在Level10保留BossRow。配置违背此规则时明确报错，不静默产生第五关Boss。
- 日志入口覆盖新增/修改函数，重点检索 `DIFFICULTY`、`Resolved`、`SPAWN Lv`、`KILL Lv`、`LEVEL START`、`PHASE`。

影响文件：`Game/DemoCombatConfig.*`、`Game/FPSDemoGameMode.*`、`Game/DemoGameState.*`、`AI/DemoEnemy.*`、`Player/DemoPlayerController.*`、`UI/DemoHUD.*`、`Tests/DemoCampaignTest.*`、`Tests/DemoSmokeTest.cpp`、`Config/Combat/*.json`、`Content/Data/*.uasset`、`Tools/Unreal/import_combat_tables.py`。流程/经济继续维护 [关卡与经济](关卡与经济.md)，验证结果维护 [调试与验证](调试与验证.md)。

## 地狱解锁、无尽流程与配置（2026-09-21）

设计上把“账号永久资格”“本轮开火记录”“本槽无尽纪录”分开：资格在 `UDemoPlayerProfile` 中由已完成战役事实推导，另外两项随检查点保存。普通战役仍为十关；无尽没有固定最终关，也不会在第十关进入 Victory。UI只显示资格，GameMode在选择、出发和恢复时再次验证，不能仅靠关闭按钮限制入口。

### 地狱资格与提示

1. 初始地狱锁定，安全区下一关终端显示“困难整轮仅手枪开火”条件。允许装备其他枪，但从第一关至第十关任何一次实际非手枪开火，即使未命中，也使本轮失格。允许冲刺、治疗及手枪已装配的弹药类型；至少实际开火一次手枪，零开火清关不算完成手枪挑战。
2. `ADemoWeaponBase::ExecuteCommittedShot`在真实射击提交后、命中伤害前调用 `RegisterWeaponShot`。资格值 `PistolChallenge`：0尚未开火，1只用手枪开火，2已失格；2在同一 RunId 内不可逆。空弹触发换弹、技能拒绝或未实际开火不计入。
3. 第一次有效开火或失格时 `StoreChallenge`只更新旧检查点的资格元数据，不把半场奖励/伤害/敌人写成检查点。必要写盘失败会退款本发弹药并拒绝射击，下一次重试；返回大厅/退出重读不会通过回退本关洗掉非手枪开火。死亡、主动放弃和通关后新一轮重新记为0。
4. 困难第十关通关且资格1时记录 `hard_pistol`，永久解锁地狱；普通困难记录 `hard` 不解锁。地狱仍打十关，完成后记录 `hell`、发配置金币，并覆盖结算页弹出“已通关最高难度，解锁无尽模式”。关闭提示回到正常结算，返回安全区即可选择无尽。Hell 枚举追加为3，旧 Easy/Normal/Hard 数值不变。

地狱默认生命×2、攻击×1.8、攻击频率×1.35；难度频率倍率作用于近战、原范围技能、飞行物、全图技能和俯冲冷却，分别有0.2秒、1秒、0.2秒、3秒、8秒下限。前摇、弹速、红光及冲刺躲避规则不因难度压缩；俯冲的固定50伤害、3秒悬停仍遵循该模块契约。敌人战术/二阶段可以继续在实例参数上调整节奏。更改倍率需关注叠加后的真实攻击间隔。

### 无尽生成与成长

无尽在已解锁后从安全区下一关终端单独选择，使用 Hell 难度作为基础。当前关数在HUD显示，不显示“/10”；清关更新本槽最高完成关数，每关依旧奖励选择、原地升级和下一关终端。死亡/主动放弃回安全区，当前关数与银币/临时成长重置，最高纪录及永久金币成长/解锁保留。三个存档各记自己的最高纪录；账号难度解锁跨槽共用。

`/Game/Data/DT_Endless`使用 `FDemoEndlessRow` 的 `Default` 行，对应 `Config/Combat/Endless.json`：

| 字段 | 默认值 | 合法范围与意义 |
|---|---:|---|
| HealthGrowth | 1.18 | 1..3，每过一关生命等级倍率乘此值 |
| DamageGrowth | 1.10 | 1..3，每过一关攻击等级倍率乘此值 |
| CountGrowth | 1.12 | 1..3，小怪数量的指数成长倍率 |
| SilverGrowth | 1.12 | 1..3，小怪与Boss单只银币成长倍率 |
| MaxAlive | 12 | 4..16，场上并存敌人上限，至少容纳Boss和三种小怪；不限制一关总数 |

第N关公式为 `基础值 × 成长倍率^(N-1)`；数量和单只银币在最终计算后四舍五入，不使用逐关取整后的值递推。基础小怪模板、数量、生命/伤害等级倍率及小怪银币来自 Level01；Boss模板和基础银币改为来自 Level10。每逢 N % 10 == 0 在三类小怪之外追加一只Boss，Boss使用相同的生命/攻击成长倍率。每5关小怪池加入远程，其他关仅近战/冲刺。物理区域按 `(N-1)%3` 循环。先应用成长，再乘 Hell 难度倍率，攻击频率沿用 Hell 配置，不逐关无限压缩冷却。

## 每五关混编、每十关Boss（2026-09-21）

本次取代旧的“每5关Boss、首关五类混编”节奏，固定战役和无尽共用规则：

| 关卡 | 小怪池 | Boss |
|---|---|---|
| 1–4、6–9、11–14、16–19等 | 近战Melee、冲刺Charger | 无 |
| 5、15、25等 | 近战、冲刺、远程Ranged三种同时存在 | 无 |
| 10、20、30等 | 近战、冲刺、远程三种同时存在 | 额外1只，不占小怪名额 |

设计：`Game/DemoEncounterRules.*`管理关号条件和随机角色分配，敌人CloseCombat/Tactics仍负责各自攻击与导航。每2只或3只小怪为一个随机袋，袋内洗牌后依次分配，下一袋重新洗牌；在随机顺序下保证每个完整袋覆盖所有允许类型。每5关至少3只小怪，保证远程不会因随机结果缺席；无尽数量公式结果不足3时在混编关补到3，其他关如果只配置1只，则从近战/冲刺中随机取一只。Boss先后顺序不消耗小怪随机序号，也不算三种小怪之一。无尽MaxAlive现在要求4..16，默认12；拒绝小于4的旧配置，保证Boss与三类小怪可以同时在场，第一批即包含全部三种小怪。

执行：`StartNextLevel`解析数值并建立计划，刷怪组件的`TrySpawn`对每个小怪调用`AssignMinionRole`、选择该角色快照再`Configure`；普通和无尽共用此路径。仅覆盖实例`Tactics.Role/bEnabled/bUseTactics`，保留模板CloseCombat前摇、冷却、速度、伤害、射程等字段；`EnemyRow`继续定义数值基线。生产战役不再使用模板MixedRoles或固定Role决定小怪类型；直接生成/测试/未来其他玩法仍可用这些旧战术接口，不删除Chaser/Flanker能力。

随机种子由RunId、关号和随机袋序号组成，不依赖全局随机数调用顺序。同一检查点重试能重现类型排列，死亡开始的新RunId会重新抽取。无尽补怪碰撞重试不会重抽角色，也不会让Boss占掉第一只小怪的序号。清关仍须等待场上和队列全部死亡，Boss关不会因为杀完三种小怪而提前结束。

配置与迁移：`Config/Combat/Levels.json`的Level05.BossRow改None，第十关保留现有Boss模板。`Tools/Unreal/upgrade_encounter_tables.py`由Editor导出现有DT_Levels，仅将Level01..09.BossRow清空，保留所有关卡怪数、属性、银币及第十关Boss选择；原始值保存在`Saved/Tests/EncounterLevelsBefore.json`，重复执行不会覆盖该备份。不存在第十关Boss模板或每5关怪数不足3时拒绝保存。执行命令沿用本文Python命令行，仅替换脚本名，成功标记`ENCOUNTER_TABLES_SUCCESS`。不要运行全量import覆盖未同步到JSON的策划调参。运行配置校验也拒绝旧第五关Boss，失败提示对应迁移脚本。

无尽Boss基础银币现在读取Level10.BossCoinReward（源默认250），再乘原SilverGrowth公式；保留第十关已经配置的实际值，不凭旧Level05奖励回退。其余两币种、永久成长、装备持久化、难度资格和检查点V5字段不变；已完成检查点仍恢复原完成关数，下一关按新节奏生成。网络/存档协议无需升级。

边界与维护：这里只调整本关生成类型与Boss周期，不增加额外三种小怪组、不改变EnemyCount含义；Boss额外占一个MaxAlive位置。暂时阻挡继续沿无尽队列重试，持续失败沿既有FailRun流程；非法角色分配明确失败。调整周期时同步`DemoEncounterRules`常量、DT_Levels验证与迁移、文档和测试。新增函数及角色日志为`ENCOUNTER_ROLE level/minion/role/seed`，可对照`AI_ROLE`与`LEVEL START`。
