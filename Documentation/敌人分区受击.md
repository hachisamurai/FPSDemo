# 敌人分区受击：PhysicsAsset、配置倍率与 GAS 结算

## 目的与当前范围

将原来的敌人整球受击改为手臂、机身和核心三个区域：打到伸出的手臂也能命中，不同部位产生不同生命伤害。所有区域仍共用敌人的一条 GAS Health；没有新增部位生命、断肢或布娃娃。当前服务单人 Standalone / PIE，网络权威命中、延迟补偿和客户端预测不在本次交付范围。

代码、配置及资产生成流程已接入，2026-09-21本轮 Editor 编译和真实 World 分区专项通过；具体覆盖与尚待验证项见本文“验证记录”。此前的武器/动画通过记录不自动代表新受击规则已验证，不能混用成功标记。

默认值为机身 **1.0**、手臂 **0.65**、核心 **2.0**，普通怪与 Boss 共用一份配置。核心奖励由真实射线先撞到哪个骨骼刚体决定，不按屏幕准星颜色或敌人整体位置猜测。

## 设计边界

### 移动碰撞与受击碰撞

- `ADemoEnemy.Collision` 保留原普通怪 48cm / Boss 115cm 球形根，继续负责移动 Sweep、墙体/同伴阻挡及原 Visibility 视线；只对 `WeaponTrace` 设置 Ignore。
- `AnimatedBody` 使用 SkeletalMesh 的 PhysicsAsset，设为 `QueryOnly`，只阻挡 `WeaponTrace`，其他通道 Ignore；不产生 Overlap，不阻挡导航，不开启刚体模拟。
- `WeaponTrace` 固定对应 `ECC_GameTraceChannel2`。`Config/DefaultEngine.ini` 注册该追踪通道并默认 Block，场景墙体继续挡弹。敌方视线、导航和飞行物保留各自原通道，不应全项目替换 Visibility。
- 动画求值使用 `AlwaysTickPoseAndRefreshBones`，隐藏或 NullRHI 下仍更新骨骼和运动学受击体；开启性能优化前必须重新检查离屏敌人的命中位置。

两套物理资产为 `/Game/Enemies/Breach/Physics/PHYS_Breach_Chaser` 与 `PHYS_Breach_Warden`，由各自网格强引用。源几何生成统计为 Chaser 15 个骨刚体 / 69 个凸体、Warden 30 个骨刚体 / 193 个凸体；后续模型变更以生成日志为准。`root`、`aim_yaw` 无直接蒙皮，也没有受击刚体。

凸体从 Blender 的独立刚性零件导出，再按 UE 实际参考骨变换转到骨局部空间。装饰灯带/螺丝由背后的实体承接碰撞；环形零件按短弧拆分，凹护板三角剖分后挤出，避免一个大凸包封住本来可见的核心孔。它们是贴合主体的简化查询形状，不是逐三角形像素级命中。

### Boss 护板与核心

四片 `shutter_*` 护板属于 Body，核心属于 Core，射线最近阻挡决定最终区域。关闭时仍保留模型自身的中心孔，玩家可以通过真实孔洞打到核心；Global 动作展开护板后，可命中的核心面积扩大。没有额外添加一个不可见大盒子把孔封住，也没有加入“只在某个技能阶段才能造成核心伤害”的 Tag 门控。

回归选用模型参考空间 `Y=0、Z=54cm` 的同一条前向射线：Global 0 秒时应先碰 `shutter_top`，2 秒展开时应碰 `core`。这是偏离孔中心的遮挡案例，不能把它描述成所有角度关闭时均无法命中核心。Boss 俯冲悬停期间的既有通用无敌仍由 GAS 属性处理，核心倍率不能绕过无敌。

## 核心运行流程

1. 敌人 Configure 设置 SkeletalMesh/AnimBP；表现组件检查 PhysicsAsset，并通过共享 `SelectValidProfile` 选择有效配置，再用 `ValidateSkeleton` 确认全部参考骨都有明确映射或禁用记录。未知骨或缺PhysicsAsset使该网格受击查询关闭并记录错误；成功重新配置会恢复QueryOnly。
2. 已支付的 Fire GA 进入 `PerformBallistics`，只在每枪开始调用 `SelectValidProfile` 验证一次 `EnemyHitProfile`。配置有效时只读快照；资产缺失或结构非法时与表现组件一样明确记录回退并使用内置完整骨名白名单，避免武器已回退而敌人仍因同一结构错误被禁用。
3. 相机到枪口的防穿墙、相机瞄准、枪口真实射线、穿透后段四条路径全部使用 `DemoEnemyHitZones::TraceChannel`。最近命中仍可能是墙，不会先被敌人外球截走。
4. `ResolveHit` 检查 BlockingHit、真实 `ADemoEnemy`、属于该敌人的 SkeletalMeshComponent、有效骨名、实际 PhysicsAsset 内的同名刚体和通道 Block。随后 `ResolveBone` 精确查表；不匹配父骨、前缀，也不把空骨默认为 Body。
5. 每颗弹先完成武器伤害、玩家加成分摊、弹药倍率和距离衰减，再乘该颗弹自己的区域倍率。按目标汇总正伤害，保留最重一颗的真实 `FHitResult`；同伤害时保留先命中的弹丸。
6. 每枪每敌只生成一个 `UDemoHealthEffect` Spec，使用原 `DemoTags::Magnitude` 传负值，Context 附带代表性 Hit。实际扣血且目标仍存活时才施加一次火/冰叠层或穿透 Cue。零倍率、不命中、配置拒绝、无敌不产生新元素层。

```text
首目标基数 = (武器每颗基础伤害 + 玩家伤害加成 / 弹丸数)
             × 弹药直接伤害倍率 × 首命中距离衰减
首目标本颗伤害 = 首目标基数 × 首目标命中区域倍率
后目标本颗伤害 = 首目标基数 × SecondaryDamageRatio × 后目标命中区域倍率
同一目标一枪伤害 = 所有对该目标的首段/后段本颗伤害之和
```

穿透保留原“沿用首命中距离衰减的理论基数”规则，不改成根据后敌距离再次衰减；最多一个后敌，忽略整只首敌后继续检查最近阻挡，墙仍终止弹道。首敌 Core 的 2 倍不能传给后敌 Arm。例如基础 20、穿透 1.25、后段比例 0.5，首敌核心为 50，后敌手臂为 8.125。

霰弹每颗独立选区域，最终合成一次 GE；同枪命中核心和手臂不会把总和统一乘某个倍率。DOT 与满层爆炸继续使用 `DA_AmmoCatalog` 的独立值，不继承触发它们的核心倍率，也不会递归产生新弹药叠层。

## 数值配置与 JSON 字段

运行时读取 `/Game/Data/Combat/DA_EnemyHitZones`，类型 `UDemoEnemyHitProfile`。武器 `EnemyHitProfile` 与敌人表现组件强引用配置，Cooker 可收集；运行时不读取工程目录的 JSON。默认配置来源为 `Config/Combat/EnemyHitZones.json`，Editor 脚本 `Tools/Unreal/import_enemy_hit_profile.py` 校验后创建/更新 DataAsset。

| 字段 | 意义与约束 |
|---|---|
| `Version` | 编辑源协议，当前只接受整数 1。 |
| `AssetPath` | 生成目录，脚本只接受 `/Game/Data/Combat/DA_EnemyHitZones`。 |
| `Regions` | 恰好 Body、Arm、Core 三项，每种出现一次。 |
| `Regions[].Region` | 稳定枚举名，不是 UI 文本。 |
| `Regions[].DamageMultiplier` | 无单位有限浮点数，0..100；0 明确表示此部位免疫，不产生伤害 GE/元素层。 |
| `Regions[].BoneNames` | 非空、精确骨名数组；所有区域与禁用列表之间均不得重名。 |
| `NonHittableBones` | 明确不参与受击的骨名；当前必须包含 `root`、`aim_yaw`，拒绝空名/重复项。 |

Arm 覆盖上臂、前臂、Chaser 武器末端及 Boss 肩部/手腕/爪；Body 覆盖机身、传感器俯仰骨、侧甲、尾翼、推进器、Boss 护板和背环；Core 只含 `core`。两套骨架取并集配置，单个网格不要求拥有并集中全部骨，但自身每个参考骨必须被明确审计。改名/新增骨时同时更新源 Rig、映射、受击几何和验证。

推荐调整 JSON 后重新导入，并复核 DataAsset。也可在 Editor 编辑资产调数，但下一次导入会按 JSON 覆盖专属配置；应把最终数值同步回源文件。单独覆盖某把武器的 `EnemyHitProfile` 时，调试绘制仍读取敌人默认配置，应同步诊断来源，避免把不同配置的颜色倍率当作实际武器结算。

几何源 `Art/Enemies/Models/enemy_hit_geometry.json` 字段：`version=1`、`units=centimetres`、`space=UE_mesh_reference`；`models[].name/mesh` 选择型号/网格；`shapes[].bone` 是刚体骨，`part/piece` 标记 Blender 零件与拆分片号，`vertices_cm` 是参考模型空间 XYZ。该文件不保存游戏伤害值，不在游戏运行时加载。

## 生成、重导入与故障处理

编辑器模块 `UDemoEnemyHitAssetLibrary` 负责烹制运动学凸体并挂回网格。脚本先校验源字段/骨名/有限坐标，再修改专属资产，保存 PhysicsAsset 与网格两个包；缺依赖、非法骨、保存失败不输出成功标记。重跑会重建脚本拥有的物理资产，手工精修应同步到源工具或另存为明确自管资产。

基础模型重导入 `import_breach_enemies.py` 显式把既有 PhysicsAsset 传回 FBX 导入器，并核对导入后仍为同一资产，不自动生成布娃娃。保留引用不等于碰撞几何仍正确：修改零件轮廓、骨参考轴或层级之后，必须重新导出受击几何、重建 PhysicsAsset、检查动画姿势和本专项。

模型几何验证改用 `SkeletalMesh.get_imported_bounds()`；挂了 PhysicsAsset 后组件包围盒可能采用物理形状，不能再把它当作 FBX 渲染尺寸。两者职责分开，防止骨骼导入工具在新增受击资产后产生误报。

- 缺少/结构非法数值资产：武器、敌人初始化及调试显示共用 `SelectValidProfile`，记录 `HIT_ZONE_CONFIG_FALLBACK`，使用完整原生白名单，绝不退回整球受击。原生默认也无效才终止选取。
- 合法配置但骨架漏配：敌人配置阶段记录 `ENEMY_HIT_CONFIG` 并关闭受击；单次查询也拒绝未知/禁用骨，不能用数值回退掩盖新骨漏配。修配置并重新Configure或生成敌人后才恢复有效查询。
- 缺失 PhysicsAsset：记录 `ENEMY_HIT_ASSET_MISSING`，玩家武器不能对该敌人造成正常部位伤害；修复资产，不用 root 球伪装修复。
- 空/非法骨、非骨骼组件、假命中：`ResolveHit` 返回 false，倍率输出保持 0，不制造默认 Body 伤害。
- 阶段切换、目标死亡、非权威 ASC：聚合结算重新检查，拒绝过期伤害。最后一只死亡导致即时切阶段时，后续条目不会继续错误结算。

## 影响文件与维护接口
