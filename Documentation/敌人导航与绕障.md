# 敌人导航与绕障

## 目的与设计

解决球形悬浮敌人直接向玩家Sweep后卡在墙角、掩体及隔墙停步的问题。本次保持小怪/Boss原移动速度、攻击力、频率与GAS伤害接口；不要求连接行为树、黑板或制作AI蓝图。`ADemoEnemy`仍是原Actor，独立`UDemoEnemyNavigation`向UE NavigationSystem查询完整Recast路线并跟随拐点，不引入一次大范围Pawn/Character继承迁移。

导航适用于现有三个平坦竞技场：保持敌人悬浮高度，路线使用地面网格投影，不提供三维飞行、跨层寻路或爬楼能力。若后续地图需要楼梯、跳跃、NavLink及人形动画，应迁移到Pawn/Character、AIController与标准PathFollowing，而不是继续扩展平面跟随器。行为树可以之后作为决策层接入，当前无需用户连线。

后续[敌人战术与第二阶段](敌人战术与第二阶段.md)已增加角色速度和战术目标：`MoveTo`跟随可达且有视线的拉距/侧翼点，和`Follow`共用`AdvancePath`执行Sweep。切换目标模式会清除旧路径；移动只由Enemy通过Tactics驱动一次，仍受施法/Frozen门控。下文原130/700cm距离描述对应旧追击/局部攻击，启用远程角色另有配置距离。

## 核心执行流程

1. Enemy Tick验证权威、存活、Combat、活玩家和4500cm范围；不满足条件清除缓存路线。Hub不追击。
2. Boss全图2秒红光前摇、原范围攻击前摇停止导航，没有独立组件Tick造成前摇期间位移；全图范围及冲刺躲避逻辑不变。
3. 停步需要距离和实际Visibility可见性同时满足。小怪130cm、Boss700cm保持原值；小怪还检查三维近战范围。Boss原局部攻击入口也增加视线判断，防止隔墙不停前摇而无法绕行；全图攻击仍不受墙阻挡。
4. 路线把敌人和玩家脚下投影到NavMesh，以`FindPathSync`获取完整路径；拒绝不可达岛的部分路径。缓存路径点值，沿下一拐点水平移动，Sweep保证不穿墙。目标移动100cm、路线走完、连续0.6秒卡住或3秒刷新周期触发重规划；重规划至少间隔0.75秒。
5. 玩家脚下不可达或走到投影点仍无视线时，最多检查12个附近候选点，要求完整路线和实际可见性。无路线停留并限频重试，不瞬移、不忽略碰撞直接冲墙。动态敌人不向NavMesh注册移动障碍，同伴碰撞采用局部滑动/侧向让行；此为简单让行，不等同于完整Detour Crowd群体调度。

## 配置与地图制作

- `Config/DefaultEngine.ini`配置一个保守导航代理：半径120cm、高240cm，覆盖Boss半径115cm。小怪共用它以确保同一路线对Boss可行，代价是小怪也不会选择不足Boss宽度的捷径。当前区域通道足够宽；后续窄通道地图可以拆分代理。
- Recast使用Dynamic，地形/掩体/终端改变时更新网格；移动敌人的Collision显式`SetCanEverAffectNavigation(false)`，不会挖空自己的路径。
- `Tools/Unreal/configure_enemy_navigation.py`加载既有`/Game/Whitebox/Maps/L_ThreeSector_Whitebox`，通过Editor桥接按`DemoArea0/1/2`找到区域，每个生成一个4000×4000×600cm Bounds。按`DemoEnemyNav0/1/2`标签复用已有体积，保留其他用户Actor，不重导入白模。
- Brush由`UActorFactory::CreateBrushForVolumeActor`与CubeBuilder创建。Commandlet先`FinishAllCompilation`等待白模StaticMesh编译完成，再提交Bounds、初始化导航几何并构建Recast；否则未编译完成的网格会被引擎排除而生成空导航。三区域投影验证成功后由Editor保存.umap。没有伪造二进制资产。脚本构建期间编辑器应关闭该项目以防未保存关卡与磁盘写入冲突。
- 白模重新导入或移动障碍后可重跑脚本。替换地图必须配置NavMeshBoundsVolume并验证可达路线；缺导航时会显示NoNavigation并等待，不采用旧直线移动掩盖配置错误。

```powershell
& 'F:/UE5.4.4/UnrealEngine-5.4.4-release/Engine/Binaries/Win64/UnrealEditor-Cmd.exe' 'F:/UE5.4Project/FPSDemo/FPSDemo/FPSDemo.uproject' -run=pythonscript '-script=F:/UE5.4Project/FPSDemo/FPSDemo/Tools/Unreal/configure_enemy_navigation.py' -unattended -nullrhi -nosound
```

## 调试、失败处理与验证

控制台`Demo.AI.DebugNavigation 1`绘制青色剩余路线与状态；设0关闭。`ENEMY_NAV`记录状态切换：Following、Repositioning、InRange、Blocked、NoPath、NoNavigation、Casting、CastingOrFrozen、NonCombat、OutOfRange、Dead。与元素弹药效果集成时，GAS移速倍率作用于导航速度，Frozen通过同一Stop入口冻结移动。高频入口保留DEMO_LOG_TICK，其余函数使用调用日志；具体投影/完整路径失败记录目标，避免把攻击停步与导航失败混淆。

专项参数`-DemoEnemyAttackTest -DemoEnemyNavigationTest`复用现有隔离存档/禁云测试入口，在真实白模创建动态实体墙：检查小怪绕墙追到可攻击位置、Boss在700cm内隔墙仍绕行、非Combat停止缓存路径、三个战斗区均有导航。原`-DemoEnemyAttackTest`独立验证飞行物、Boss前摇、冲刺躲避回血及取消生命周期。本地构建/运行结果另在本文末尾如实记录，不能把编译当作实际寻路成功。

边界：无网格、投影失败、不可达目标可能暂时停留；目前不让敌人传送或越墙补偿。极密人群仍可能排队，需要之后增加Crowd或攻击站位分配。玩家在高处时可以寻找可见远程位置，但不会让平面悬浮敌人爬上箱子。World暂停冻结重规划时间和移动；死亡/终局/卸载丢弃点值，没有悬空异步回调。

## 影响文件与维护

Runtime：`AI/DemoEnemyNavigation.h/.cpp`、`AI/DemoEnemy.h/.cpp`、`FPSDemo.Build.cs`；Editor：`Navigation/DemoNavigationAssetLibrary.h/.cpp`与模块依赖；配置：`Config/DefaultEngine.ini`；工具：`Tools/Unreal/configure_enemy_navigation.py`；测试：`Tests/DemoEnemyNavigationTest.cpp`及EnemyAttackTest入口；地图：`Content/Whitebox/Maps/L_ThreeSector_Whitebox.umap`。对应概述同步维护`关卡与经济.md`、`Whitebox.md`。

`Player/DemoPlayerProfile.cpp`同步补充EnemyAttackTest隔离标记，保证此导航专项在非Editor打包游戏也使用随机临时档，而不读取正式武器解锁档；RunSaves和CloudSync既有同名隔离规则继续复用。

导航参数改变必须重新制作/保存地图并检查Cook版本；改变Boss碰撞半径时同步代理清障半径。同步查询按少量30怪白模限频，扩大规模后先用Unreal Insights测量，再考虑异步路径与Crowd。此实现只保证原单人权威移动，不新增完整联机支持。
