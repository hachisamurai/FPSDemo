## 目的与美术规则

采用灰白装甲、深灰机械结构和克制的敌方指示灯，与玩家青色武器形成阵营区分。三种普通怪未来依靠外形识别，减少对颜色的依赖；当前共用追击型网格，灯带按战术角色显示红/蓝/紫。原占位球只在外观资产缺失时显示，不再作为玩家子弹命中体。

| 类型 | 模型轮廓与活动部件 | 复用关系 |
|---|---|---|
| Chaser 撞击者 | 约 1m 主体，楔形前甲，双短臂和撞击板，双推进器 | 普通怪共用骨架与 AnimBP |
| Ranged 哨戒者 | 独眼、双侧炮管，水平延展装甲，炮管后坐 | 同骨架替换网格、动作配置和附件 |
| Flanker 游猎者 | 扁平主体、短后掠装甲、外露推进器，侧倾明显 | 同骨架替换网格、动作配置和倾斜参数 |
| Boss 镇压核心 | 约 2.4m 主体，厚肩甲、双节机械臂、四片核心护板和背部能量环 | 第 5/10 关共用另一套骨架与 AnimBP |

第 10 关后续计划通过肩甲/背环/核心护板变体强化轮廓，保持骨架兼容。等级成长继续由数据表决定，造型变化不暗中修改血量、攻击力、移动速度或掉落。普通怪48cm、Boss115cm球形根继续用于移动/通道检查，手臂等伸出部分由独立骨骼受击体查询。修改附肢轮廓时必须同步重建PhysicsAsset，不能只调导航球的半径。

金属件采用刚性蒙皮、明确铰链和结构间隙；软管才采用渐变权重。首版动画无 Root Motion，导航移动根与视觉悬浮分离。交付追击型 LOD0 为 16,124 三角形，Boss 为 32,820；运行性能仍需结合同时怪物数、材质槽和特效测试，不能只由面数承诺性能。

## 骨骼与资源契约

已建普通怪 `SKEL_Breach_Drone`（17 根骨骼），后续三模型共用相同名称、层级、轴向和参考姿势；不要分别导入三套同名但无兼容关系的 Skeleton。已建 Boss `SKEL_Breach_Warden`（32 根），供后续两关变体共用。当前源 Rig 是直接 FK 骨架，未制作 IK/自定义动画师控制器；FBX 导出必要变形骨骼与 root，禁用额外 leaf bones。

```text
root                           导航参考原点，首版动画中保持不动
└─ body                        悬浮/前倾/侧倾/受击
   ├─ core                     核心转动、蓄能
   ├─ aim_yaw → aim_pitch       感应器/主炮瞄准
   ├─ arm_l → forearm_l → weapon_l
   ├─ arm_r → forearm_r → weapon_r
   ├─ armor_l / armor_r         机械护板开合
   ├─ fin_l / fin_r             后侧导流板
   └─ thruster_l / thruster_r   推进器转向
```

上图为已交付普通怪层级。Boss 使用独立肩部、腕部、机械爪、四片核心护板与背环控制，仍保持 root/body 的职责；完整层级见导出清单。两套骨架已建立 `Muzzle_L/R`、`CoreFX`、`ThrusterFX_L/R`、`HealthBar` Socket；非人形不强行匹配 Manny/Lyra 人形骨架。

已交付普通怪动作：Idle、Move、Melee、Fire、Hit、Death；Boss另外增加Area、Global、Rise、Hover、Dive、Recovery、Rage。Area/Global在单段动作内完成蓄力、释放、回收，视觉转向由C++平滑驱动主网格，目前无单独Turn动作。死亡为失力侧翻下沉并保持末帧，无布娃娃/解体特效。

## 动画蓝图复用与用户维护方式

已实现 `UDemoEnemyAnimInstance : UAnimInstance` 为两个 AnimBP 的 C++ 公共父类。`ABP_Chaser` 服务普通怪，`ABP_Warden` 服务Boss；图为Idle/Move按bMoving混合→FullBody Slot→Output Pose。创建、配置和敌人接入已经完成，无需修改模板第一人称AnimBP。下表是后续完整动画/联机输入契约；当前仅实现Speed、bMoving、bMovementFrozen缓存，动作优先级和死亡由表现组件/GA管理，尚未实现瞄准快照、状态复制等其余字段。

复用边界：

- 同骨架普通怪：复用 AnimBP，通过外观/动作配置选网格、Montage、移动倾斜幅度、悬浮频率等，不复制三份 EventGraph。
- 同骨架 Boss 变体：复用 Boss AnimBP，替换装甲和动作资源。
- 骨架结构不同：共用 C++ 状态读取和接口；需要不同 AnimGraph 或按需使用 AnimBP Template/Linked Anim Layers。模板不自动解决骨骼、IK 和蒙太奇资源兼容。
- 仅换颜色、装甲附件、同骨架动画：优先改配置。新增活动肢体、骨骼层级、动画槽位或全新行为：需要更新绑定和对应 AnimGraph。

拟定外观配置资产 `DA_EnemyAppearance_*`：保存 SkeletalMesh、AnimClass、各攻击 Montage、Socket 名称和悬浮/倾斜参数。只承担表现，不复制战斗数值；怪物模板通过外观 ID 引用。以后联机只复制稳定的外观/角色标识，由本地资产映射加载，不每帧同步资产指针或骨骼矩阵。

## AnimInstance 数据与当前实现差异

当前 `ADemoEnemy` 继承 AActor，不是 Pawn/Character；`UDemoEnemyNavigation` 通过 `AddActorWorldOffset` Sweep 驱动。不能照搬 `TryGetPawnOwner → CharacterMovement → Velocity` 的人形模板；仅启用 bReplicates/ReplicateMovement 也不会得到 CharacterMovement 的预测和平滑。

拟定只读动画输入快照，Actor/组件保有唯一玩法状态：

| 输入 | 含义与单位 | 来源/生命周期 |
|---|---|---|
| LocalVelocity | 主体局部移动速度 cm/s | 服务器移动结果；客户端使用网络运动/插值结果，传送时重置差分 |
| AimYaw/Pitch | 相对身体的目标朝向，度 | 服务器选定目标得到；客户端仅平滑表现 |
| Role/AppearanceId | 普通怪类型与外观标识 | 出生配置，不由 AnimBP 选 AI 策略 |
| bMovementFrozen | 当前禁止导航移动 | 现有 Frozen 状态，不等同禁止攻击 |
| bDead/bEnraged | 死亡/二阶段持续状态 | 服务器状态/已复制 GAS 状态，初始化时读取当前值 |
| AttackVisual | 当前技能类型、序号、阶段/开始时间 | 仅特殊程序化表现使用；Montage 播放位置交由 ASC |

`GetOwningActor()` 获取敌人；主线程绑定 ASC 标签、读取玩法数据并形成快照，动画工作线程只使用安全缓存，不能在 ThreadSafe Update 中直接访问任意 Actor/ASC/World。初始化需要处理网格、ASC、外观资产的到达顺序；更换网格/销毁时解绑，防止委托保留旧 AnimInstance。

可参考 Lyra 的 `FGameplayTagBlueprintPropertyMap` 把已存在于本机 ASC 的标签映射到 AnimInstance 变量。该映射只负责本地数据接线，不是网络复制机制；新 AnimInstance 必须读取已有标签状态，不能只等待未来变化事件。当前项目尚未提供所有拟定状态 Tag，不应把本文标签名直接当作已注册资源。

## 推荐的联机同步职责

采用“服务器权威战斗 + GAS 状态/技能 + ASC Montage 复制 + 客户端 AnimBP 姿势计算”，不把全部动画转换为 GameplayTag。

| 内容 | 建议同步渠道 | 本地处理 |
|---|---|---|
| 位置、朝向、移动速度 | Actor/移动组件的权威运动复制 | 客户端插值，再计算倾斜与悬浮；不每帧 RPC 发姿势 |
| 瞄准方向 | 限频/量化复制朝向或必要目标信息 | 本地平滑炮管，不让客户端自行选伤害目标 |
| 冰冻、燃烧、死亡、二阶段 | GE 授予的复制 Tag，或明确的权威 RepNotify 状态 | 驱动状态机和材质，选择一个唯一权威来源 |
| 攻击、重击、施法 Montage | GA → PlayMontageAndWait → ASC PlayMontage | 模拟代理按 ASC 复制数据播放、校正和停止 |
| 火焰/冰霜、枪口、命中火花、音效 | 按事件/持续状态区分 GameplayCue | 客户端表现；Cue 不结算伤害 |
| Boss 长前摇/预警圈 | 持久化的攻击快照（技能 ID、序号、开始时间、时长、位置） | 按同步服务器时间恢复剩余前摇，不能只依赖一次 multicast |
| 健康、伤害、攻击权限、奖励 | 服务器 GAS 属性/GE 与规则 | 客户端读取和展示，不用动画回调直接扣血 |

AI 技能建议服务器执行（ServerOnly），由敌人的 ASC Montage 复制向相关模拟客户端呈现，不要求每个客户端运行一份 AI Ability。ServerOnly 不会阻止 Actor/ASC 的其他复制通道。玩家未来若有需要即时响应的技能，可选择 LocalPredicted，由服务器校验；不把玩家预测机制套在无拥有客户端的 AI 上。

普通怪 ASC 可以继续考虑 Minimal 模式：GE 授予的标签和 Cue 有相应复制机制，但 Minimal 并不表示自动复制项目所有 C++ 变量，也不替代 AttributeSet 各属性的复制声明和 OnRep。所有人可见的敌人状态不可误设成 OwnerOnly。

UE5.4 的 `AddLooseGameplayTag()` 不会自动网络复制。持续控制效果优先由服务器 GE 授予/移除标签；如确实使用 replicated loose tag，需要管理本地与复制容器的计数和清理。不要假设普通 loose tag 或任意 Ability 标签加上后所有客户端都能立即收到。连续两次攻击若标签始终为真，无法表达第二次播放；短暂开关也可能被网络更新合并，因此 Tag 不能代替动作实例、Section 或播放时间。

`PlayMontageAndWait` 必须找到已初始化 Avatar 上正确的 SkeletalMesh/AnimInstance，AnimGraph 必须有对应 Slot。已在Configure设置主网格和AnimClass后调用RefreshAbilityActorInfo，并通过运行时断言核实ASC读取到该AnimInstance。敌人保持一套主动画网格，避免多个组件时误选。表现GA通过Task调用ASC PlayMontage；没有额外multicast。当前Actor外观/死亡/目标/属性仍未完成整套联机改造，不能仅凭这条播放路径宣称联机已支持。

悬浮/推进器轻微摆动允许本地计算。若要所有客户端看到同一节奏，可使用复制的出生种子与服务器时间求相位，无需同步每根骨骼。客户端可因延迟略有姿势差异，权威命中与截止时间必须一致。

## Boss 技能示例与既有语义

1. 服务器验证 Combat、生命、冷却和冲突状态，启动全图技能，固定当前关卡和一次性攻击序号。
2. 建立前摇快照并由 ASC 播放对应 Montage，镜头可见端开始护板开启、背环充能及 Cue。
3. 晚收到或重新进入相关范围的客户端按服务器开始时间恢复剩余前摇；已结束的旧序号不得重播。
4. 固定 2 秒结束时，服务器按既有冲刺躲避规则结算，命中/躲避回复仍由服务器决定；范围攻击仍保留 0.9 秒预警。骨骼动作或播放速率适配规则时长，不能反过来改变原有窗口。
5. 死亡/换阶段/取消时服务器关闭该攻击；清理 GA Task、Montage、标签与持续 Cue。客户端收到取消后恢复合法姿势，不能在本地 Notify 再补一次伤害。

当前 Frozen 语义是“定身不封攻击”，因此 AnimBP 只抑制移动与相关倾斜，不能直接暂停整个 SkeletalMesh 动画而吞掉开火/蓄力。若未来要完全冻结攻击，需要单独修改玩法规则和取消链路。死亡状态持久化到尸体移除，受击短动作不能覆盖死亡；后加入者也应看到正确死亡/二阶段状态。

AnimNotify 用于音效、特效或服务器认可的动画事件，客户端 Notify 不拥有伤害权限。Dedicated Server 若依赖骨骼 Socket 命中或服务器 Notify，需要相应动画 Tick 策略及性能验证；本方案优先保留服务器独立的技能时间轴，不把伤害截止时间绑在客户端动画帧上。瞬时 Cue 不保证迟加入补播，持续效果与长预警应能从当前权威状态重建。

## 实施顺序、验证与失败处理

1. 概念/骨骼契约（已完成）：两款代表造型与普通怪/Boss 复用边界。
2. Blender建模/绑定及动作（已完成）：两套基体、19个正式动作、独立关节诊断源，root无位移。

## 战斗动画与运行时接入

### 目的与设计

把已制作机械骨架接入单人玩法，采用“原玩法拥有结算，C++表现组件请求GAS动作，薄AnimBP混合姿势”的边界。无需把整个Actor改为Character，也不让动画工作线程查询世界或ASC。两套骨架独立编译图，但共用C++状态和播放管理。当前动作是可编辑的机械FK首版，未制作IK、复杂瞄准偏移或物理布娃娃。

### 执行流程与接口

1. Enemy构造创建唯一AnimatedBody及Presentation；Configure按bBoss选择DA_Chaser/DA_Warden，赋网格和AnimClass，刷新ASC ActorInfo并授予表现专用GA。正常隐藏旧球体；外观资产缺失时保留仅供显示的备用球并打印ENEMY_ANIM_CONFIG错误。该备用球不参与玩家枪弹查询，缺失PhysicsAsset或骨名映射必须修复资源，不能把视觉回退理解为整球受击回退。
2. UDemoEnemyAnimInstance在游戏线程通过GetOwningActor取得敌人，用世界位置差分得到cm/s（Actor自身没有CharacterMovement速度）。1500cm以上单帧变化视为传送；12/5cm/s阈值避免移动/静止抖动。Frozen只抑制bMoving，FullBody Slot继续播放。
3. Play(Action,Seconds)查当前外观Actions映射并仲裁优先级：死亡100、Boss阶段60、近战/发射40、二阶段20、受击10。低优先级不能中断当前动作；Rage排队到当前Montage结束，其他低优先级请求跳过并记录原因。同级新请求可以重播，适应原有独立攻击冷却。
4. 同步激活UDemoEnemyAnimationAbility，由PlayMontageAndWait管理播放/完成/中断/取消。普通Melee仍是即时接触结算，所以动作首帧为撞击延伸后回收；Fire在弹体成功生成后启动后坐。没有新增第二份伤害回调。
5. Boss Area视觉在0.9秒附近爆发、Global在2秒爆发，权威Timer仍精确保持0.9/2秒。俯冲原GA每次SetPhase请求Rise/Hover/Dive/Recovery，并按真实阶段时长设置播放速率；原飞行碰撞、悬停3秒无敌、落地伤害继续由原GA处理。动作是24fps，非整数帧时间附近的视觉插值不能反向改变规则时钟。
6. 死亡当帧取消旧技能/表现、关闭碰撞并通知GM一次，随后播放1.5秒Death。Death Montage关闭自动淡出以保持末帧，1.65秒移除Actor；提前换图/清理Actor可以截断尸体，但不延迟清关或奖励。EndPlay与CancelPendingAttacks精确取消表现GA。
7. 主网格在表现组件中平滑朝向当前单人目标，碰撞根和导航保持原逻辑。现阶段子弹仍从碰撞中心发射防止枪口跨墙，Muzzle Socket预留后续特效。灯带EnemyTint延续红/蓝/紫角色辨识与Boss二阶段紫红状态。HUD从HealthBar Socket取世界位置，继续屏幕空间绘制血条和图标。

## 模型与骨架实作交付

| 类型 | Blender 源 | UE SkeletalMesh | UE Skeleton | LOD0 / 骨数 |
|---|---|---|---|---|
| 撞击者 | `Art/Enemies/Models/Breach_Chaser_Rigged.blend` | `/Game/Enemies/Breach/Meshes/SK_Breach_Chaser` | `/Game/Enemies/Breach/Skeletons/SKEL_Breach_Drone` | 16,124 三角形 / 17 骨 |
| 镇压核心 | `Art/Enemies/Models/Breach_Warden_Rigged.blend` | `/Game/Enemies/Breach/Meshes/SK_Breach_Warden` | `/Game/Enemies/Breach/Skeletons/SKEL_Breach_Warden` | 32,820 三角形 / 32 骨 |

源文件分别保留 63/113 个独立零件，倒角修改器可调；每个零件一个顶点组，权重为 1。导出副本才合并、展开 UV 和应用倒角。骨骼实际控制见 `enemy_rig_manifest.json`：普通怪 core、传感器、双臂/前臂/撞击板、侧甲、后板、推进器；Boss 另有四瓣护板、六根机械指骨、背环主骨及六个环段。root 和 aim_yaw 仅作为层级父骨，无直接几何权重；其余 15/30 骨均实际影响网格。

整体包围盒（包括双臂/背环）：追击型约 深67.5×宽152×高89.1cm；Boss 约 深145.3×宽330×高279.1cm。原点在主体附近而非地面，悬浮高度由敌人外观配置。48/115cm球形根现在只承担移动与既有非武器视线职责，玩家子弹查询附肢/机身/核心的PhysicsAsset；修改轮廓时必须同时核对受击体、导航通道和场景相对大小，不能假设主体尺寸就是所有附肢的总尺寸。

FBX 源位于 `Art/Enemies/Models/FBX/`：两个 `SK_Breach_*.fbx` 和两个 `A_Breach_*_RigCheck.fbx`。骨骼 FBX 不携带正式战斗动画。QA 动作导入 `/Game/Enemies/Breach/QA/`，24fps、4秒，对应 Blender 时间线 1..97 帧；中立→展开→中立→反向小幅运动→中立。Blender 打开后选中 Armature，Pose Mode 可直接调骨；播放时间线检查 FK。UE 可打开 QA AnimSequence 预览同骨架网格，随后为正式动画另建资产，不能把 RigCheck 作为攻击 Montage 接入。

共享材质位于 `/Game/Enemies/Breach/Materials/`，六个角色为 Frame/Armor/Steel/Rubber/Amber/Dark；线性颜色、金属度和粗糙度与清单对应，Amber 发光。UV0 自动展开；三档 LOD 由 UE SkeletalMesh 简化器生成，具体减面按引擎默认设置，不等同手工优化后的性能预算。初版建模不生成自动布娃娃；当前已新增专用查询PhysicsAsset，按真实刚性零件拆凸体并保留核心孔，跟随骨骼动画，不开启物理模拟或约束。制作/配置/调试方法见[敌人分区受击](敌人分区受击.md)。

每套 Skeleton 有六个挂点：Muzzle_L/R、CoreFX、HealthBar、ThrusterFX_L/R。UE5.4 Python 的 Skeleton.Sockets 受保护，新增编辑器桥接 `UDemoSkeletalAssetLibrary::SetSkeletonSocket` 通过原生 Skeleton 对象更新；输入为模型空间厘米变换，按真实骨参考父链计算局部挂点。重复执行复用同名对象。挂点必须随模型修改一起重导入；未来同 Skeleton 不同体型若需要不同挂点偏移，可扩展 Mesh Socket，不能用共享 Skeleton Socket 覆盖不同型号需求。

`ValidateRigidSkin` 直接读取 UE LOD0 渲染权重及每 section BoneMap，确认不是只有骨动画、模型却未蒙皮。新增桥接和验证只在 `FPSDemoEditor` 模块，未引入运行时编辑器依赖。静态工具函数没有 this，因此入口沿用现有编辑器库的 `UE_LOG(LogFPSDemo,...[CALL])` 格式；输入拒绝和成功结果另有日志。

### 源清单字段（JSON 不支持注释）

- `version=1` 与 `units=centimetres`：导入契约版本及所有输出空间坐标单位。
- `palette`：每项 `[线性RGBA, metallic, roughness]`，后两项范围 0..1。
- `enemies[].name/mesh/skeleton`：型号、网格名、骨架名；`parts/triangles` 为独立源零件数/LOD0 导出三角形数。
- `bounds_cm`：逻辑 UE 最小/最大 XYZ 范围，导入组件的逐端点距离容差 0.30cm。
- `bones[]`：稳定名称、父骨名（root 的父为 null）、参考骨头模型空间坐标 `head_cm`；UE 层级/骨数必须完全一致，骨位置容差 0.15cm、缩放容差 0.005。
- `sockets`：父骨 `bone`、模型空间 `world_cm`、仅审计用的 `blender_bone_local_cm`。UE 侧从 world_cm 与自身参考骨架反求局部空间，不直接套用 Blender 骨轴。

完整导入流程：创建/同步材质→导入网格与专用骨架并显式保留既有PhysicsAsset绑定→创建 LOD→检查真实蒙皮及参考姿势→写挂点→导入诊断动作→采样根、手臂和核心轴心→保存并打印成功。可选只读验证跳过资源写入，再检查所有已序列化内容。渲染几何尺寸使用GetImportedBounds读取，不以新增物理体决定的组件Bounds代替。首次制作受击资产或修改模型/参考骨后，继续按分区文档导出受击几何并重建PhysicsAsset；单纯保留引用不能保证改动后的形状/轴仍贴合。

制作脚本会覆盖自己拥有的源文件、FBX、预览和专用 UE 资产，重导入会更新参考姿势及 QA 动作。后续手工修改应复制版本或同步到脚本，尤其绑定轴心变化会影响旧动画，不能直接覆盖已经制作的生产动画。导入失败立即中止，不输出成功标记；前面已保存的资产可能存在，可修正后重跑。诊断动作重新导入出现“新播放长度与现有相同：96帧”是等长更新提示；轴/单位/骨数/权重错误则属于失败，不应忽略。
