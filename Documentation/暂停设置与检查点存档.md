# 暂停、设置与检查点存档

## 目的与规则

Esc暂停真实World，显示返回安全区、设置、返回大厅、退出四项；再次Esc恢复。子弹、AI、AbilityTask和冷却随游戏暂停，UI保持可操作。打开时停止连射、取消装填与开镜，恢复不自动开火。奖励/终端窗口在暂停下面保留，恢复后回到原窗口。

玩家已处于`Hub`安全区时，点击“返回安全区”仅调用`ReturnHubPressed → CloseOverlay → RefreshMenuInput`，关闭Esc覆盖层并解除World暂停；不检查成长确认、不重置货币/属性/武器、不写检查点、不重新生成Pawn或切换地图。若Esc下层原本有终端/出发窗口，仍恢复该窗口及其输入限制。判断依据是GameState阶段而非坐标，关间`Intermission`仍按原有放弃流程处理，Victory仍走通关续玩入口。日志`Return hub: already in Hub; closing pause overlay only`用于确认命中该分支；入口不在Pause页时仍拒绝。本行为无需新增配置，影响`Player/DemoSessionMenus.cpp`、`DemoPlayerController.h`及本文。

此分支验证方式：在安全区打开Esc并点击返回安全区，确认菜单关闭、World恢复且角色位置/当前枪弹药/两币余额及属性不变；再从已打开的终端覆盖Esc重复操作，确认回到终端。战斗中返回仍应遵循原有成长确认规则。

2026-09-21安全区关闭暂停修正：保存关闭Editor后Development Editor完整构建通过（`Saved/Logs/HubPauseCloseBuild.log`）。使用现有`-DemoSessionTest -DemoVictoryContinuationTest`真实渲染回归（`Saved/Logs/HubPauseCloseValidation.log`），step143验证安全区返回后无覆盖菜单、金币/永久属性/价格不变；日志记录本次Hub分支和`page=0 paused=0`，未触发旅行。该回归随后在独立的退出游戏步骤114失败（`EXIT_SAVE pause failed`），因此仅将本次关闭菜单行为记为通过，不宣称整个Session回归通过。终端下层恢复本次仅检查共用CloseOverlay代码路径，未单独实机验证；`Tests/DemoSessionTest.cpp`同步修正了原先描述为重载World的旧注释。

金币不清空，用于安全区属性升级；银币来自击杀，用于关卡清场后的原地终端升级。仅完整十关通关按难度发金币，默认简单500/普通750/困难1000/地狱1500。通关、死亡及未通关主动放弃返回安全区时，清空银币、银币购买及免费获得的临时属性/技能成长、银币各项价格；保留剩余金币、金币永久属性/各项价格、武器解锁及本槽实际装备。主动放弃有临时成长才先确认，取消仅关确认框。通关回Hub可选择更高难度；死亡/主动放弃重新创建Pawn后恢复原主武器、持有库存及主副槽选择，均按基础容量加金币永久容量补给。真正新建存档仍默认只带手枪。完整经济规则见[关卡与经济](关卡与经济.md)，装备修复流程与专项验证见[武器库与玩家存档](武器库与玩家存档.md)。

死亡当帧立即保存重置后的Hub检查点，死亡结算页直接返回大厅/退出也先重试必要保存，不会读回死亡前临时成长或银币，金币永久成长正常恢复。普通未结束战斗返回大厅仍使用出发检查点，丢弃半场银币与耗弹；此前完整战役通关的金币保留。
开始游戏先显示三个存档栏，隐藏大厅主菜单；时间为首次创建时FDateTime::Now的本地时间。空栏必须确认创建；已有栏读取后恢复。损坏/未来版本栏位不能作为空栏覆盖。当前不提供删除存档功能。

用户选择检查点自动保存：安全区、出发前、清关等待奖励、领取奖励后、终端购买/选枪后保存。读档回到安全区或已完成关卡的备战位置，Reward恢复待领奖，旧Victory存档自动转入可操作的续玩安全区；不会恢复飞行物、敌人精确位置或半截技能。难度只在安全区下一关终端弹窗选择，进入第一关后锁定，关间仍使用原来的出发确认。

编辑器运行的数据仅在同一次试玩内有效：PIE、SIE与Editor Standalone都使用独立的本地临时档，停止试玩即清空；同一次运行中返回大厅再选已有存档仍可继续。正式非Editor游戏目标保留跨进程持久存档。画质、分辨率和鼠标设置属于设备偏好，停止试玩不清空；诊断日志、截图也保留。

## 所有权与执行流程

### 退出前保存状态弹窗（2026-09-21）

大厅“退出”与Esc“退出游戏”共用 `QuitPressed → QuitSaving`。先暂停并绘制窗口，约0.15秒后执行 `SaveBeforeQuit`：显式保存永久档案，再由GameMode保存检查点。Combat仍保留进入战斗前的检查点，不保存敌人、飞行物或半场所得。UI分别展示本地保存和云端等待状态，不用显示字符串判断成功。

打包游戏本地落盘后调用 `UDemoCloudSync::BeginExitSync`；控制器在暂停时用 `PlayerTick → PollExitSync` 等待最多30秒。成功依据是类型化Complete：旧上传回执已匹配并落盘，最新三个槽快照、永久修订、装备偏好及分批通关记录均无需继续上传。只收到某个HTTP 200或旧回执不足以退出。成功提示显示1秒，然后执行标准 `UKismetSystemLibrary::QuitGame`。

失败窗口提供“重试保存 / 仅保存本地并退出 / 取消退出”。本地保存失败会禁用仅本地退出；重试重新写两种本地档，再启动云屏障。云失败或超时保留耐久队列，明确选择仅本地退出时再检查一次本地保存，下次联网补传。冲突不自动选择本地或云端，需取消退出并回大厅处理。取消按钮或Esc恢复原大厅/暂停页，后台同步可继续，但晚到回执不再触发退出。外部旅行销毁Controller时也取消退出意图。

Editor目标没有Cloud/API子系统：显示“试玩检查点已保存；结束试玩将清空本次数据”，不等待网络。打包版本关闭云配置时明确显示本地模式。`Config/DefaultGame.ini`既有API地址、启用与HTTP超时配置继续生效；退出屏障30秒、首帧延迟0.15秒、成功提示1秒为代码常量，不改变存档结构。此流程覆盖游戏内退出按钮，不承诺强杀进程、崩溃、断电或操作系统直接关闭窗口时还能等待上传。

设计与所有权：Controller拥有退出页和本地结果，GI CloudSync拥有网络/队列；HTTP使用既有弱UObject委托，退出流程不捕获Controller、不跨线程操作UI、不在Deinitialize阻塞。仅新增 `Player/DemoExitMenu.cpp` 分类承载退出功能；同步更新 `DemoPlayerController.h/.cpp`、`DemoSessionMenus.cpp`、`DemoCloudSync.h/.cpp`、`UI/DemoSessionHUD.cpp`、`Tests/DemoSessionTest.cpp`、`Tests/DemoCloudTest.h/.cpp`。HUD仅绘制和路由，成功页及失败页共用720×520缩放布局；所有入口、失败和状态转换均记录日志。

验证入口：Editor使用 `-DemoSessionTest -DemoExitSaveTest -DemoSessionCapture`，覆盖大厅/暂停取消、取消后不延迟退出、隔离Profile真实只读写盘失败、禁用离线退出、重试、成功截图与实际QuitGame。打包Development使用 `-DemoCloudTest=exit-online|exit-offline -DemoCloudTestId=<新GUID>`；online在旧上传在途时再保存新检查点，必须补传后才能退出；offline需给该测试进程覆盖不可用API地址，验证失败→重试→取消→仅本地退出。不可用Editor开启云测试，也不能把测试GUID换成正式玩家账号。实际通过记录见[云存档运行与验证](云存档运行与验证.md)。

`UDemoRunSaves`为GameInstanceSubsystem，维护三个UDemoRunSave值快照和一次跨地图恢复请求；SaveGame仅保存稳定ID/数值，不保存Actor。GameMode负责采集/恢复/重置流程；Controller处理意图与暂停输入，Canvas HUD呈现模态页面。永久UDemoPlayerProfile独立保存通关/解锁。

已有存档→校验→选择槽→OpenLevel ResumeRun→新PS/ASC/Pawn→StartRun创建安全区→还原数值/已持有武器→按检查点生成终端/待领奖；Victory则进入统一续玩接口。新World避免残留计时器、死亡标签、敌人注册表与旧UI指针。

### 通关续玩与旧存档恢复

第十关`FinishLevel`先切换Victory再按锁定难度发一次金币、登记武器解锁，恢复“基础GAS属性+金币永久增量”，清空银币、银币价格和临时属性/免费技能奖励；恢复满永久生命、补给武器并保存Victory。前九关不发金币，旧Victory读取也不再次发放。

`ContinueAfterVictory`是结算按钮/Enter、Victory的Esc返回安全区及已有Victory读取的统一入口。幂等确认通关记录、清理残留临时成长、创建安全区终端、新RunId后保存Hub；金币、金币永久属性/各项价格、武器解锁/库存保留，击杀统计累计。CreatedLocal始终保留首次创建时间。

终端/通关记录校验失败保留文件并显示原因；保存失败保留内存，出发重试。`HasRunUpgrades`比较当前属性与永久基线，纯金币成长不弹放弃确认。无活动槽开发World通过GI临时值快照执行同样的重置/恢复，不把永久属性挤进URL；停止试玩销毁该快照。

### 成长来源V3、弹药V4、挑战V5与旧档兼容

当前Version=5。V4引入本槽`UnlockedAmmoIds`/`SelectedAmmoId`，购买扣币与解锁同步写入同一检查点，装配成功也保存；死亡/通关重置保留。V1/V2执行下述成长迁移后，连同V3补普通弹，再执行V5迁移；未知未来版本仍保护文件。弹药规则见[弹药类型与Debuff设计](弹药类型与Debuff设计.md)。

V5新增`bEndless`（无尽模式）、`BestEndlessLevel`（本槽最高完成关数）、`PistolChallenge`（0未开火、1只手枪、2失格）。无尽每关都有检查点，Reward/Intermission可超过十关，没有Victory；死亡/主动放弃清空当前进度及临时成长，保留最高纪录。普通战役/地狱仍十关。旧V1..V4没有开火来源证明，已完成关数>0时本轮资格设2，Hub从0重新记录；不凭旧困难胜利补发地狱解锁。旧存档的金币、永久成长与弹药保持原迁移规则。

真实开火会先把资格变化写到原检查点，战斗中返回大厅/退出也重试该元数据保存，不保存半场敌人或战利品；因此射过其他武器再读档不会恢复资格。首次资格变更写盘失败拒绝实际开火并退回弹药，后续可重试。通关/死亡/放弃重置新RunId时清除本轮资格。永久档案SchemaVersion=3，由`hard_pistol/hell`通关事实推导地狱/无尽解锁，跨三个槽共用；进入存档和出发前均验证资格。配置、接口、依赖文件、边界及2026-09-21实际回归见[战役配置与难度](战役配置与难度.md)。后端须先更新至支持检查点V5，Editor仍仅使用临时本地数据。

V3增加`UpgradeProgress`，同时保存永久属性增量与两币种各三项价格计数。GAS合计字段仍保留，读档直接设置合计，不能重放永久GE；`ResetTemporaryGrowth`才计算永久基线。检查数组长度、非负次数、合计一致、永久值不超过总属性。价格按币种/具体属性独立上涨，不再用Purchases定价。

V1/V2没有足够信息还原购买来源，按可推算的旧金币总购买数退还旧价格花费（V2使用GoldPurchases，V1仅Hub按总数），旧属性暂留本轮，六项价格重置；不伪造永久购买记录。先迁移版本3防止重复返还，再补弹药字段与V5挑战元数据，余额上限1亿。具体字段、公式、边界与Editor迁移测试见[关卡与经济](关卡与经济.md)。未来版本保护原档；云DTO支持到V5，部署API必须先于新客户端。

### 编辑器会话隔离与停止清理

`WITH_EDITOR`决定数据策略，不使用`GIsEditor`区分游戏数据：Editor可执行文件的`-game`也必须临时保存。每个GameInstance生成`DemoEditorRun_<PID>_<GUID>_0..2`及`DemoEditorProfile_<PID>_<GUID>`槽名，主档/备份都通过UE SaveGame API创建。跨OpenLevel保留同一GI，停止PIE或正常退出时两个存档子系统的`Deinitialize`只删除自身精确槽名，并释放缓存；新一次Play重新生成GUID与默认手枪解锁。

编辑器停止独立进程的引擎路径`UEditorEngine::EndPlayOnLocalPc`调用`TerminateProc`，可能跳过GI退出。为此`FPSDemoEditor/Save/DemoEditorSessionCleanup`监听`BeginStandaloneLocalPlay`，由父Editor持有子进程查询句柄，每秒检查退出后补做清理。仅枚举当前项目SaveGames直接子目录，匹配已退出PID、完整GUID、0..2槽号和可选_Backup后缀，逐个调用平台删除API；运行中的进程、正式档、名字近似但格式错误的文件均不删除。模块卸载解绑委托/Ticker，关闭查询句柄不会终止游戏。

网络子系统`UDemoCloudSync`与`UDemoApiClient`在WITH_EDITOR构建不创建，因此编辑器既不读取云进度也不上传试玩数据。显式云回归参数同样不能覆盖编辑器临时策略。若整个Editor被系统强杀/断电，父进程也无法执行清理，可能留下孤立临时文件；这些随机槽永不被新会话读取，不会恢复旧试玩进度。删除失败会写Error日志，不宣称文件已清理。正式存档不会在Editor停止时被删除。

## 设置

使用UE UGameUserSettings处理分辨率、总体画质与全屏/窗口模式，派生配置类保存鼠标灵敏度0.1..3.0；角色视角输入乘倍率。界面编辑暂存值，点击应用才提交，返回放弃未应用改动。显示模式改变需在倒计时内确认，未确认回退旧显示模式，计时使用真实时间不受暂停影响。设置存于本地GameUserSettings.ini，不属于战役槽。

分辨率预设1024×768、1280×720、1600×900、1920×1080、2560×1440、3840×2160，并保留当前自定义尺寸。画质低/中/高/极高映射Engine总体Scalability 0..3；现有混合档显示“自定义”，不编辑画质时保持原值。显示模式为全屏/无边框全屏/窗口。确认时间15秒，Esc或超时恢复原显示值；已应用画质与鼠标倍率保留。未增加音量或改键设置。

### PIE的Esc冲突

UE5.4默认将`PlayWorld.StopPlaySession`绑定到Esc，会先于游戏输入结束PIE。`Config/DefaultEditorSettings.ini`通过引擎`ProjectDefinedChords`把本项目的主停止键设为Shift+Esc，单独Esc留给游戏。JSON中的BindingContext/CommandName/ChordIndex指定命令及主键，Shift=true，其余修饰键=false；仅编辑器使用，不影响打包输入。需重启已打开的Editor读取配置。个人显式快捷键优先于项目默认；若个人配置仍绑定Esc，可在Editor Preferences → Keyboard Shortcuts → Stop修改。停止工具栏按钮仍可正常使用。

## 持久字段与配置

非Editor构建的正式文件为`Saved/SaveGames/DemoRun_0.sav`至`DemoRun_2.sav`，各有`_Backup`后缀备份；`DemoPlayerProfile.sav`独立保存永久武器和难度解锁。Editor使用上述会话槽，不读写这些正式文件。存档由UE SaveGame API创建，不手工生成二进制文件。Version=5；增加字段/调整基线需同步Validate、恢复代码和版本迁移，不能仅改变默认值。

| 数据 | 用途 |
|---|---|
| CreatedLocal / SavedUtc | 首次创建本地时间 / 最近保存UTC；重开保留创建时间 |
| RunId | 本轮挑战GUID，普通检查点读档保持，放弃/死亡重开及通关续玩生成新值，旧Victory先幂等记账 |
| Phase / CompletedLevel / Difficulty | 安全检查点类型、已完成关数、选定难度；普通战役0..10，无尽可超过10 |
| bEndless / BestEndlessLevel / PistolChallenge | 模式、本槽最高无尽纪录、本轮只手枪开火资格；纪录保留，资格随新一轮重置 |
| Coins / SilverCoins / Kills | 保留金币 / 可清零银币 / 累计击杀 |
| Purchases / GoldPurchases / SilverPurchases | 总购买次数 / 安全区金币次数 / 关间银币次数；各币价格独立 |
| MaxHealth / Health / DamageBonus / MagazineBonus | GAS基础数值，不保存临时GE或死亡标签 |
| HealAmount / DashSpeed | Pawn技能成长：HP与cm/s，新局基线35/1300 |
| Weapons / PrimaryId / ActiveSlot | 已持有稳定武器ID及独立弹匣/备用弹药、主武器、当前1/2槽 |

## 边界与失败处理

格式Version=5（可迁移V1..V4），校验阶段/关卡、枚举、模式与最高纪录一致性、有限数、非负经济与武器ID；有效旧档先备份，写失败在UI显示，不静默假定保存成功。新档创建失败不旅行；主动离开/重置的必要保存失败时保持当前界面供重试。未持有/未解锁武器不能仅靠修改存档获得。编辑器和自动化隔离GUID槽，退出只删除本实例文件。同一次试玩返回大厅不会销毁GI，不触发清空。

## 分类、依赖与维护

代码分类到Save/、Settings/，UI与Controller扩展原模块；GameMode、Character和WeaponComponent提供采集/恢复接口。无需新增二进制UI资产。Config/DefaultEngine.ini指定GameUserSettingsClassName，字段因INI配置机制在此说明。保留现有GAS、武器终端与永久解锁设计。所有新增UObject入口/回调记录DEMO_LOG_CALL，高频渲染/查询用DEMO_LOG_TICK；编辑器自动化对象不是UObject，使用同类别UE_LOG等价记录入口。

影响文件：`Save/DemoRunSave.*`、`Settings/DemoGameUserSettings.*`、`Game/DemoSessionFlow.cpp`及`FPSDemoGameMode.*`、`Player/DemoSessionMenus.cpp`及`DemoPlayerController.*`、`UI/DemoSessionHUD.cpp`及`DemoHUD.*`、`Characters/DemoCharacter.*`、`Weapons/DemoWeaponBase.*`和`DemoWeaponComponent.*`、`Interaction/DemoInteractable.cpp`；`Player/DemoPlayerProfile.*`负责编辑器解锁档隔离/清理。配置为`DefaultEngine.ini`/`DefaultEditorSettings.ini`；测试为`Tests/DemoSessionTest.*`及旧流程测试适配，PIE/强制停止/键位检查分类到`Source/FPSDemoEditor/Tests/`；父进程清理在`Source/FPSDemoEditor/Save/`，模块入口负责回调注册/解绑。
