# Breach 四款武器模型：静态源与骨骼运行资产

## 目的与当前状态

按已确认的`Art/Weapons/Concepts/Breach_Weapons_Concept_v1.png`制作Breach工业风格武器：深灰金属、灰白护板、橡胶握把和少量青色标识。手枪紧凑，步枪使用弯弹匣，散弹枪采用粗枪口、宽护木和可拆卸弹匣，狙击枪以长枪管及光学镜形成不同轮廓。

2026-09-21换弹框架接入后，四个正式武器BP已从整枪StaticMesh迁移到轻量SkeletalMesh，支持真实弹匣、套筒、枪栓动作。原静态模型、FBX、UE资产和预览保留，作为可编辑源与历史交付，不再作为四把运行武器的外观。GAS、主/子AnimBP、声音及运行时流程统一见[武器系统](武器系统.md#第一人称四枪换弹动画层与同步音效2026-09-21实现)。

枪械动作在Blender制作；手臂在UE Editor采样实际机械Sequence，通过离线TwoBoneIK烘焙。两者按同一归一化时间配对，手臂不是在Blender枪械场景内同时制作。运行时公共主图提供待机支撑手IK，换弹时关闭该IK并使用已烘焙双手动作。

## 骨架、坐标和美术变更

共同层级为：

```text
weapon_root
└─ body
   ├─ magazine
   ├─ slide                         手枪
   └─ bolt                          步枪、散弹、狙击
      └─ charging_handle            仅步枪、散弹
```

每个硬表面顶点只绑定一根骨，权重为1.0。weapon_root/body全程固定，所有骨Scale=1，不包含角色根运动。整体举枪、倾斜和后坐由手臂控制骨ik_hand_gun带动；机械动画只移动内部部件，防止枪身位移重复叠加。

本次在保留轮廓的基础上补齐必要机构：

- 手枪原源主要为底板，增加握把内的弹匣盒体，盒体与底板同属magazine骨；slide支持空仓后锁及释放。
- 步枪/散弹增加可抓取的拉机柄，随bolt机械轨迹运动。
- 狙击栓柄仅在新骨骼源中移至UE +Y侧，配合右手拉栓；原静态源不变，排壳口饰板仍固定在机匣上。
- 当前一直显示真实magazine骨；左手追随同一轨迹，弹匣在视野下方完成交接。默认不HideBone、不生成第二个手部弹匣，不建立可拾取道具或物理弹匣。

所有新manifest位置均为UE模型空间厘米，+X朝枪口、+Y右、+Z上。Blender制作源采用厘米单位，并以已有Y镜像/FBX轴契约导出；UE导入比例为1，不再手动乘100。FBX重新导入以及UE导入都检查真实骨位置、父子关系和模型边界，不能只看画面大致朝前就认定坐标正确。

## 导入、手臂烘焙与运行配置

1. `Tools/Blender/build_breach_weapon_animations.py`读取旧静态源并在独立后台进程中拆分、补机械件、刚性蒙皮，生成4个网格、8个机械Action和可选弹匣副本；源文件与新输出目录分离。
2. 生成器以60Hz烘焙并重新导入实际FBX，验证单骨1.0权重、骨层级、厘米边界、根恒定、Scale=1和片长。普通/空仓使用同一枪Skeleton，四枪Skeleton相互独立。
3. `Tools/Unreal/import_fp_weapon_animations.py`导入网格与机械Sequence，按材质槽复用Breach材质，创建/更新Muzzle、Grip_L、Sight、Grip_R Socket并保存Skeleton。
4. `UDemoFPSequenceAuthoring::Build`以模板手臂FP_Rifle_Idle首帧为基准，采样已导入机械Sequence，在同phase求弹匣/枪栓与手腕目标，离线解双手IK并写入标准UE骨轨道。保留原手臂Skeleton和蒙皮，更新已有ik_hand_gun及手部辅助骨轨迹。
5. `UDemoFPAnimationAuthoring::Build`创建真实WeaponBasePose接口、固定主图、公共层、4个配置子类；ConfigureLayer写一份AnimSet。运行时主图通过LinkedAnimLayer选择当前武器姿势，FPAction播放开火/换弹，公共TwoBoneIK负责待机支撑手。
6. 导入器只修改4个既有BP的表现字段：Mesh、StaticMesh、AttachSocket、AttachOffset、WeaponAnimLayerClass及旧Idle/Fire/ReloadAnimation。已有伤害、弹药、射速、装填秒数、解锁、UI图标等配置保留。

当前BP必须满足：

| 字段 | 当前值/约定 |
|---|---|
| Config.Mesh | 对应SK_Breach骨骼枪 |
| Config.StaticMesh | 空；非空仍优先于Mesh，且带武器层的骨骼配置预检会拒绝该组合 |
| Config.WeaponAnimLayerClass | 对应ABP_FP_Pistol/Rifle/Shotgun/Sniper |
| Config.AttachSocket | 手臂已有ik_hand_gun |
| Config.AttachOffset | 恒等变换，不再使用旧GripPoint逆旋转 |
| Config.MuzzleSocket | Muzzle，来自当前骨骼外观 |
| Config.IdleAnimation / FireAnimation / ReloadAnimation | 空，由子AnimBP的AnimSet统一提供 |
| Config.bHideSupportArm | 沿用当前武器值，手枪true、长枪false；换弹临时恢复手枪左臂 |

`OnConstruction / InitializeForOwner → ApplyVisualMesh → 挂接ik_hand_gun → CommitEquip → LinkAnimClassLayers → GAS与双网格表现`。

保留原WeaponMesh根组件以兼容蓝图序列化；新模式在根设置骨骼枪，并清空StaticWeaponMesh子组件的资源。旧静态模式仅兼容未迁移外观。实际弹道、枪口粒子和声音位置读取当前外观的Muzzle；武器切换及开镜隐藏整个Actor，两组件均无碰撞。

手臂整体位置由DemoCharacter设定，当前Mesh1P相对相机仍为(-10,0,-147)cm。动作基础锚点为模板OldGrip位置+(20,0,8)cm，使用单位基础旋转后再叠加动画侧倾；枪继续依附独立ik_hand_gun，狙击右手拉栓不会带走枪身。调整镜头构图不能通过恢复旧GripPoint挂接偏移绕过新锚点；需检查待机、完整换弹和瞄准恢复。

当前已烘焙姿势由`Art/Player/Animations/fp_pose_profiles.json`统一配置：右腕在锚点空间为(-10.5,1.5,-2)cm，右肘IK极点为右肩+(12,50,-45)cm；狙击空仓过渡在真实枪栓插值上增加最大6cm的枪局部+Y绕行，幅度为sin(pi×BoltAlpha)，完全握持端点为0。右腕不再沿用模板GripPoint相对偏移。左腕手枪(3,-14,-24)cm、三把长枪(12,-2,0)cm；左肘作者极点为左肩+(30,-18,-28)cm，公共主图已与该平面对齐。配置只用于离线烘焙，游戏仍读取标准UE动画；每项字段及完整算法见[武器系统](武器系统.md#机械骨架手臂烘焙与稳定挂点)和制作目录README。

联合制作场景为`Art/Player/Animations/Breach_FP_Reload_Workbench.blend`，`WORKBENCH_README.md`说明四枪集合、旧UE/候选Action与机械枪挂接。`CurrentUE/`保留修正前12动作FBX及矩阵，作为旧穿插证据；`FinalUE/`保存23:42新进程从当前UE实际资产只读导出的12动作、独立原手臂网格及60Hz/关键阶段矩阵。两次导出各核对33个读取包SHA256不变，目录名FinalUE仅表示最新导出来源，不代表最终视觉结论。

`stock_collision_proxy.json`含真实枪托零件的OBB及三角面，`forearm_skin_radius.json`同时保留前臂与上臂蒙皮厚度。骨轴/腕点通过仍可能漏掉护甲或twist区域；必须在同场景检查变形后的实际蒙皮，特别是狙击右手伸向枪栓及回握阶段。工作台候选与最新UE动作需明确区分，不能只对候选运行一次几何检查便宣布UE成品通过。

## 清单与配置维护

`weapon_animation_manifest.json`不能直接写注释，主要字段在本节和`Art/Weapons/Animations/README.md`解释：

| 字段 | 用途与单位 |
|---|---|
| version / units / coordinates / fps / root_motion | 当前结构版本1、厘米与UE轴方向、60Hz、无根运动 |
| weapons[].model / mesh / blend | 稳定枪型、网格名、独立Blender源；生成器据此限制输出范围 |
| weapons[].skeleton | 导出清单内的骨架标识；UE当前实际生成资源名为SK_Breach_{Type}_Skeleton，不把两者误认成同一包路径 |
| bones[].name / parent / head_cm | 骨名、父骨及模型空间参考位置；不能把head_cm直接当父骨局部位置写入 |
| bounds_cm / triangles / material_roles | 参考姿势边界、LOD0三角数和真实材质槽，用于单位/轴/材质校验 |
| sockets.*.bone / world_cm | Socket父骨与模型空间厘米位置；Muzzle、Grip_L、Sight、Grip_R用于射击/制作标定 |
| magazine_center_cm / magazine_grip_cm / magazine_grip_offset_cm | 弹匣枢轴和抓握目标；用于离线对齐，不增加运行时弹药状态 |
| bolt_grip_cm / mechanism_grip_bone | 机械操作手腕目标及对应骨，狙击右手跟随实际bolt轨迹 |
| parts[].name / rigid_bone / vertices | 源零件、单骨归属和顶点统计，改模时用于检查错误蒙皮 |
| clips[].name / variant / seconds / frames / fps / loop | 动作名、版本、时长、帧间隔数、采样率及非循环约定；样本包含末端关键帧 |
| clips[].stages / sound_events[].name / phase | 归一化阶段及声音语义/时间；声音导入后由游戏时钟事件触发，不用Notify补弹 |
| clips[].hand_targets | 稀疏机械位置参考；手臂烘焙优先采样实际导入Sequence，不仅在这些记录之间插值 |
| magazine_presentation / model_changes / magazine_visibility | 可选静态副本几何、机构改动及真实弹匣显示约定；首版不启用手部替身 |

改机械轨迹、时长、骨层级或抓握位置后，需要重建机械资源、重新烘焙手臂并核对声音阶段。只修改材质或不影响握持/枪口的几何无需修改GAS；修改枪口坐标必须同步清单和Socket，保证画面与实际弹道一致。SoundEvents等运行配置字段详见武器系统文档，避免在两处维护互相冲突的表。

## 边界、失败处理与本轮状态

- 缺源文件、未知材质/骨、非刚性权重、FBX轴/单位/片长不符、骨架或Socket错误、蓝图编译/保存失败均中止，并输出明确日志。失败前可能已保存前置专属资产，修正后可重跑。
- 运行时缺手臂挂点拒绝初始化；缺枪口记录警告并使用现有相机偏移回退。四个交付网格在导入和专项中必须有真实Muzzle，不能以回退算成功。
- 相机到枪口的防穿墙射线保持原规则，长狙击枪模型不会使射击穿过近墙。持枪网格没有物理碰撞或敌人受击用途。
- 所有参考姿势和Socket都基于现有模板手臂及每枪独立骨架。更换手臂或重新定向骨轴需要重新标定和烘焙，不能直接复用当前腕位置当通用骨架配置。
