# 调试与验证

## Windows 运行包资源遗漏（2026-09-20）

### 原因和证据

用户在 Windows Launch On 运行时点击开始，收到 `Missing combat DataTable or incorrect row type; import Content/Data tables`。这是 `DemoCombatConfig::Validate` 对“表为空”和“行类型错”的共用提示；本次日志已经进一步证明是 **Cook/Stage 遗漏资源**，不能仅凭这句提示让用户重新导入或修改表结构。

- `Saved/Logs/FPSDemo.log` 启动记录（UTC 10:31:32）明确报找不到 `/Game/Data/DT_Enemies`、`DT_Difficulties`、`DT_Levels`；UTC 12:12:06 的配置拒绝是稍后点击开始时的结果。
- `Content/Data` 中三张源 `.uasset` 都存在；原 `Saved/Cooked/Windows/FPSDemo/Content`、`Saved/StagedBuilds/Windows/FPSDemo/Content` 及 `Manifest_UFSFiles_Win64.txt` 未收录它们。
- 同一启动还缺少 `/Game/Weapons/Blueprints/BP_Weapon_Rifle` 和 `/Game/Weapons/Input` 的输入资产，并报 `Missing combat InputAction assets`。
- 实际 UAT 命令是 BuildCookRun 的 `-build -cook -map=... -stage -deploy -run`（Launch On）。表及武器由原生默认软路径/运行时 LoadObject 加载；这次按地图收集依赖没有覆盖上述路径。编辑器能从完整 Content 加载，不代表平台 Cook 输出包含它们。

### 修复、设计与维护

在 `Config/DefaultGame.ini` 的 `[/Script/UnrealEd.ProjectPackagingSettings]` 下增加：

```ini
; 三张战役 DataTable 的运行包依赖。
+DirectoriesToAlwaysCook=(Path="/Game/Data")
; 四个武器蓝图、战斗输入 Action/Mapping 的运行包依赖。
+DirectoriesToAlwaysCook=(Path="/Game/Weapons")
```

对应编辑器 Project Settings → Packaging → Additional Asset Directories to Cook。仅显式纳入两个运行目录，不要求全项目 Cook，也不改表数据、GAS 或关卡逻辑。引擎 `UCookOnTheFlyServer::CollectFilesToCook` 读取该配置，将目录内资产及其依赖交给平台 Cook，再由 Stage 收集；其语义也见 [Epic 打包配置文档](https://dev.epicgames.com/documentation/unreal-engine/API/Developer/DeveloperToolSettings/UProjectPackagingSettings)。项目仍不依赖运行时读取 `Config/Combat/*.json`。

修改 `.ini` 后建议保存工作并重启编辑器，让设置面板重新读取配置；重新 Cook 和 Stage/Package，旧部署包不会自动更新。用新的输出目录可避免误启动旧包。不需要重新导入三张源表，也不要把未 Cook 的 `.uasset` 直接复制到旧发布包；打包可能采用 Pak/IoStore，检查时需同时看 Cook 产物、容器和运行日志。

新增运行时软路径目录必须同步此清单；若未来使用 AssetManager/PrimaryAssetLabel，应保持明确的 AlwaysCook 规则并重新验证。未覆盖的目录仍可能发生相同问题；不应为了绕过配置校验而回退硬编码数值。影响文件：`Config/DefaultGame.ini`、`Game/FPSDemoGameMode.h` 的收集说明注释、本文、`战役配置与难度.md`、`武器系统.md`；没有改 C++ 行为，无需为本次配置修复重编引擎。
